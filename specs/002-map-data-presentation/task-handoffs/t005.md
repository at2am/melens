## Boundary semantics

Missing counts stay null and measured zero stays zero. Unknown locations retain null geometry; unlocated facts are excluded from viewport totals and use their own scoped page. `noMatching` needs verified area/time evidence, complete query results, zero unresolved results and an exact zero total. Source-incomplete results keep unknown totals. At final live integration root aligned the validators with frozen v1: a paginated partial page may preserve an exact full-snapshot total independently proved by the service. Actual Dart transport decoded live viewport total 212 and member total 23 on one-record partial pages. Item source/time/assertion/lifecycle and geographic precision remain typed and preserved.

GeoJSON positions are two-dimensional `[longitude, latitude]`; invalid positions, unclosed rings, negative/fractional counts, unsupported enum values and missing required nullable fields are rejected. UTC instants preserve up to six fractional digits, reject invalid calendar dates and never interpret unknown provider clock text as an instant. Every request window is capped at 31 days with exact microsecond comparisons; statistical date-only period bounds are independent of that limit. Response decoders tolerate additive optional v1 fields; request decoders reject unknown fields.

Freezed's supported factory-level `JsonSerializable` annotations are documented with a file-local `invalid_annotation_target` suppression because Freezed forwards them to generated concrete classes. No project-wide lint rule was disabled.

## Sample scope

Samples retain fixed fixture times, source ids, attributions and `dataMode=sample`. The repository never contacts a live endpoint or fills missing values/positions. Unrepresented layers, windows or jurisdictions retain unknown/partial evidence rather than a zero claim. A bounded sample page loses its exact total when truncated.

Select the historical sample scenario explicitly; mode mismatches are rejected so detail reads cannot substitute current observations for historical ones under the same fixture snapshot. Fixture snapshots are deterministic sample contexts. Unknown snapshot ids, unknown item ids and unavailable details are explicit repository errors. Superseded/cancelled requests do not publish sample results. The partial fixture's continuation is intentionally unavailable; complete production pagination, snapshot lifecycle and time/filter controllers belong to later integration tasks.
