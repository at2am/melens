## Frozen integration API

```ts
type ZoomBand = 'overview' | 'district' | 'neighbourhood' | 'closeUp';

nominalZoomBand(zoom: number): ZoomBand;

aggregateLayer(layer: LayerResult, options: {
  zoom: number;
  bounds: Bbox;
  band?: ZoomBand;
}): {
  band: ZoomBand;
  items: MapItem[];
  groups: ReadonlyMap<string, {
    aggregate: AggregateItem;
    members: readonly MapItem[];
  }>;
  excludedIds: string[];
};
```

T014/T025 should retain the returned groups under the same source snapshot. Members are parsed, detached and deeply frozen original MapItems with their exact stable IDs and versions. Member reads page those members with the original snapshot context and recheck publication/retraction; they never query every record in the navigation bbox. `memberIds` and `resultRange.returnedCount` enumerate/count the loaded member records. The returned `items` are ordered by layer/id/version and replace only presentation items; the layer's original query totals and pagination remain separate.

The nominal bands use 11/14/17 boundaries. A trusted caller can pass an already resolved client band; `band` is an internal API option, not a new wire field. T025 must keep the request's presentation zoom consistent with the active client hysteresis band because the frozen ViewportQuery carries only zoom. Fixed per-band projected cells prevent regrouping for every small camera movement within one band. Colocated/dense compatible records remain grouped even at closeUp and retain their list members.

## Truth and geometry decisions

- Point groups stay in their original layer and separate source sets, assertion/lifecycle, metric definitions, readout granularity, exact observation windows, anomaly baselines/directions and effective-time semantics. Equivalent trailing-zero UTC fractions normalize; differing microseconds never merge.
- Pedestrian metric is distinct effective source-scoped sensor count, unit `sensors`. Two same-source sensor observations in the same group preserve both member references and count one sensor. Passage counts remain on the original members, including measured zero and null. The metric definition states that passages can repeat persons and are not summed here.
- Anomaly groups contain eligible, producer-classified anomalous results only. They count distinct source-scoped result IDs and share window/baseline/direction. Unclassified/ineligible results are excluded from anomaly presentation.
- Event, disruption and planning group metrics count loaded records; they do not assert deduplicated occurrences, unique people, measured speed or complete source coverage. Plans retain explicit plan assertion/lifecycle. Unknown or open-ended times remain unknown.
- `resultRange.totalMatching` is null for every partial group even if the enclosing layer supplies an exact query total. A complete group's exact count is its actual matching loaded member records, never the layer-wide total.
- Aggregate geometry is MultiPoint containing the exact original member coordinates in stable ID order. T023 confirmed it can render one navigation symbol at the first original member point. No guessed centroid or bbox polygon is returned. Location role is `unknown`, with explicit group-navigation evidence.
- Navigation bounds tightly enclose the loaded members. A degenerate axis uses one adjacent representable float inside the request bbox because the frozen Bbox requires nonzero dimensions. This minimal padding is navigation metadata; it does not enlarge source geometry or claim a new affected area.
- Lines, MultiLines, source polygons and statistical-area indicators retain original geometry and geographic precision. No verified scope-safe simplifier was available, so the conservative implementation leaves extents unchanged. No street/building metrics are inferred.
- Null/unlocated, inactive sensors, out-of-bounds points and mention-only/unsupported point-localized news are excluded. Reliable news/area shapes pass through without later-story grouping or deduplication. Existing aggregate shapes pass through without regrouping.
- Input is capped at 1,000 records and 2 MiB, output presentation items at 2 MiB. Conflicting versions of one stable ID are rejected. T014 still owns the global cross-layer item limit and final envelope byte limit.
