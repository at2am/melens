## Boundary APIs

`parseViewportQuery` and `parseViewportQueryJson` accept unknown JSON and return the schema-derived `ViewportQuery`. Requests reject unknown fields, enforce the operational Melbourne bbox, finite zoom, distinct registered layers, ordered UTC windows of at most 31 days, statistical date-only filters, one boundary level/vintage, page limits and paired snapshot/cursor continuation.

`parseViewportResponse`, `parseMapLayerCatalog`, `parseMapItemResponse`, `parseMapItemPage` and `parseMapItem` validate the frozen response shapes. Response objects ignore optional additive fields while preserving all recognized values. The viewport parser optionally receives `expectedRequest` for echoed identity/mode/layers and noMatching window coverage. Envelope parsers accept `production: true` to prohibit sample output. All parser helpers enforce uncompressed byte budgets before returning data.

Named schemas are exported for every request/response family, nine item variants, sources, geometry and coverage. Missing counts/values and geometry remain null; GeoJSON is 2D longitude/latitude with closed polygon rings. Viewport items cannot contain unresolved geometry. Items are distinct and ordered by layerId/id/versionId. NoMatching requires complete, verified area/time coverage and exact empty items/totals/unresolved count. The validator bounds 1,000 items across the whole viewport, not per selected layer.

UTC instants support at most six fractional digits. Ordering, exact duration bounds and normalized identities preserve microseconds; zero-padding an equivalent instant does not change its identity. No Date.parse millisecond truncation is used to decide temporal ordering or cursor equality.

`normalizedViewportIdentity` produces a viewport-v1 hash of the frozen normalized common context. It excludes request id, layers and opaque tokens. `validateSnapshotCursor` uses injected server-owned snapshot/cursor resolvers, checks query family, full identity, original layer authorization, source-version watermark, five-minute lifetime and current public access. It does not accept a token merely because its syntax looks valid. Snapshot/cursor binding schemas document the trusted resolver interface. No signing key is required for the chosen opaque-token store design.

## Evidence

The full TypeScript package compiled with Node 24.18.0 / TypeScript 5.9.3, then `node --test dist/test/map-contract.test.js` passed 14 of 14 tests. Tests parse all 14 frozen example documents using their correct envelope/item shapes, including all seven viewport states and all nine item variants. Negative cases cover malformed coordinates/rings/counts/times, missing filters, unknown request fields, incorrect noMatching coverage, partial/cursor consistency, query identity, raw UTF-8/byte bounds, cross-route tokens, source-watermark changes, expiry and publication retraction.

## Integration limits

This task supplies validation and typed resolver interfaces. It creates no map route, persistent snapshot store, source admission decision, coverage producer or query adapter. Authentic coverage evidence and exact full-query totals must come from the admitted query/coverage owners; schema validation cannot establish those facts from empty rows. Future detail/member/list routes must also enforce current admission and snapshot scope through their server-owned resolver. Root must run the final shared package suite after remaining task changes.
