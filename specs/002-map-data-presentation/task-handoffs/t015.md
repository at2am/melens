# T015 — 2D map surface and core geometry renderers

Implemented the bounded Google Maps Web surface and point, multipart line, polygon-with-holes and pedestrian count-circle renderers. Layer toggles filter the supplied DTOs immediately without replacing the mounted map or issuing camera commands. T017 owns `MapScreen` integration.

## Public integration contract

- `MapSurface(layers: List<LayerResult>, enabledLayers: Set<MapLayerId>, dataMode: MapDataMode, ...)` consumes canonical DTOs. Initial camera defaults to Melbourne at zoom 14.
- Root state owns `selectedItemId`, `onItemSelected(MapItem)` and `onAggregateSelected(AggregateMapItem)`. Selection passes the original object, preserving source/time/context fields. The root can drill aggregates into `details.bounds` using its own controller.
- `onMapCreated`, `onCameraChanged`, `onCameraIdle` and `onMapTap` forward the public plugin callbacks. Overlay updates do not reset the initial camera or animate it.
- `MapSurfaceConfiguration` exposes the render plan and callbacks to the injectable `MapSurfaceBuilder`. Widget tests also override `mapSurfaceReadinessProvider`, so the fake builder needs no SDK/network.
- `MapAggregateRenderer` is the hook for T023's `buildAggregateRenderPlan(BuildContext, List<AggregateMapItem>, String?, ValueChanged<AggregateMapItem>?)`. Core rendering skips aggregate styling; their unit, range and partial semantics belong to T023. Aggregates still remain selectable through the object list when no hook is installed.
- `CoreRenderPlan` contains public `markers`, `circles`, `polylines`, `polygons` sets and supports `merge`. `buildGeometryRenderPlan` preserves supplied geometry for T023 reuse. `isDrawableMapItem` is the common location-safety guard.

## Truthfulness and accessibility

Count-circle ground area is fixed at **16 square metres per sensor passage**, with radius `sqrt(count × 16 / π)`. It is never normalized to the viewport or clipped to a minimum/maximum radius. The visible legend names the scale and says to compare the same observation window; it explicitly disclaims population density. A measured zero has radius zero and retains its sensor identity marker. A missing or invalid negative count has no count circle. Exact zero/count/unknown text stays readable independently of the overlay.

GeoJSON coordinates stay longitude/latitude at the boundary and are converted to `LatLng(latitude, longitude)`. Multipart parts and polygon holes remain intact. Missing, invalid or contradictory locations are not assigned a point or area centroid. Ambiguous and inactive pedestrian positions remain undrawn. The keyboard-accessible object list can expose a supplied unlocated DTO without fabricating a marker; separately fetching scoped unlocated pages belongs to T016.

Direct pedestrian DTOs are guarded too: the effective location must cover the entire observation window, with a known start and either an open end or an end at/after the observation-window end. Invalid intervals stay undrawn. Anomalies have an explicit type label; transport disruptions show their lifecycle and planned assertions in text, independently of colour.

The sample-data label remains visible when the base map is loading, unavailable or missing its key. SDK readiness is controlled by app-scoped Riverpod providers using the existing `GoogleMapsWebApiLoader`; errors do not auto-retry and the explicit retry does not disclose raw error/key text. `GoogleMap` uses `MaterialUiCompatibilityBridge` because the pinned plugin reads legacy Material themes. Flutter controls are outside the platform-map rectangle, so no overlay pointer interceptor is needed in this surface.

The legend and readiness messages scroll within bounded rectangles. The sample label remains above the legend scroll area. The object-list heading scrolls with its rows, so opening mobile bottom details does not force intrinsic text heights beyond the remaining map surface. Shrinking the surface preserves the mounted map and its camera.

## Validation

On 2026-10-01, with the pinned SDK:

```sh
cd app
/opt/homebrew/bin/fvm flutter test --no-pub test/features/map/ui/renderers/core_renderers_test.dart
/opt/homebrew/bin/fvm flutter test --no-pub test/features/map/ui/map_surface_test.dart
/opt/homebrew/bin/fvm dart analyze lib/features/map/ui/map_surface.dart lib/features/map/ui/renderers/core_renderers.dart test/features/map/ui/map_surface_test.dart test/features/map/ui/renderers/core_renderers_test.dart
```

Results: **19 T015 tests passed**, scoped analysis **No issues found**. Tests cover fixed area scaling, zero/missing/negative readings, coordinate order, multipart lines, polygon holes, invalid/missing/ineffective locations, original-object selection, keyboard Enter selection, explicit anomaly/disruption labels, persistent sample labels, readiness failure/manual retry, layer-toggle camera retention and aggregate hook routing. Responsive regressions verify a 390×241 surface remains selectable and retains its camera after shrinking, a 390×120 missing-key surface does not overflow, and retry stays reachable in a short failed-readiness rectangle. Root generated `map_surface.g.dart` and merged/generated the queued strings from `t015.l10n.json`.

The joint run also passed the current **10 T017 `map_screen_test.dart` tests** (29 tests total), including the 390×844 mobile bottom-details regression that originally exposed the overflow.

## Remaining acceptance boundaries

Real browser map rendering, Maps authorization after SDK readiness, restricted origins and plugin gesture behavior require an authorized real key and T017 browser integration. Fake-map tests cannot certify those. Native Maps setup is intentionally an explicit unavailable state and remains a separate acceptance gate. This delivery does not certify data-source publication, live source coverage, deployment, P0 end-to-end acceptance or the agent request context.
