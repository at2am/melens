# T010: Topic defaults and session layer controls

**Date**: 2026-10-01
**Status**: Implemented and validated. Root merged the queued English ARB additions and completed Riverpod/localization generation.

## Changes

- Added `LayerTopicPreset` metadata using the canonical `MapTopic` and `MapLayerId` enums. City activity defaults to pedestrian counts, anomalies and disruptions, with optional events, development projects and boundary context. Nearby news defaults to news. Area comparison defaults to rent, with Census as its alternative filled metric; boundary and City activity helpers remain independently selectable.
- Added a session-lived annotated `layerControllerProvider`. Every topic retains its own immutable enabled-layer set. Switching a topic restores that topic's adjustments; a fresh provider scope starts with defaults. Context is a layer category, not a fourth selectable topic.
- Enabling rent or Census atomically replaces the previous filled metric without changing auxiliary layers. The selected metric is exposed for legend integration. Disabling every layer is permitted and remains a user selection state, rather than a no-matching-data or no-coverage claim.
- Added `LayerPanel` with English localized titles, topic chips and layer switches. Later topics are visible but disabled by default for the P0 shell. Availability is supplied by the canonical catalog; omitted evidence remains unknown, and selected/unavailable layers are not silently hidden. Sample catalog metadata uses the existing persistent sample label.
- Controller and panel do not read a repository, change the camera, choose source admission, create filters or initiate later-story fetching. Product gates and data admission remain owned by integration.

## Public interface

`layerControllerProvider` returns `LayerSelectionState`:

| Member | Type / behavior |
| --- | --- |
| `topic` | Canonical selected `MapTopic` |
| `availableLayers` | Immutable preset-ordered `List<MapLayerId>` for current topic |
| `enabledLayers` | Immutable `Set<MapLayerId>` for immediate drawable filtering |
| `enabledLayerIds` | Immutable preset-ordered `List<MapLayerId>` for request/agent context |
| `filledAreaMetric` | `rent`, `census` or `null`; never both |
| `layersForTopic(topic)` | Immutable saved/default set for the requested selectable topic |
| `isLayerEnabled(layer)` | Current-topic toggle value |

The notifier exposes `selectTopic(MapTopic)`, `setLayerEnabled(MapLayerId, bool)` and `toggleLayer(MapLayerId)`. Context-topic selection and layers outside the active preset throw `ArgumentError` without changing state. Repeating the same selection is a no-op.

`LayerPanel({MapLayerCatalog? catalog, Set<MapTopic> selectableTopics = const {MapTopic.cityActivity}})` consumes the provider. Catalog input describes source availability; it does not reset user intent. Integration may widen `selectableTopics` only after the later product gates are accepted.

The seven new English ARB key/value and description pairs are queued in `t010.l10n.json`. Root owns applying them to `app_en.arb`, localization generation and `layer_controller.g.dart` generation.

## Integration notes and limits

- T015 filters rendered objects against `enabledLayers`; toggle updates do not reset map position. Camera and viewport state stay outside this controller.
- T017 must not send `layers=[]`, which is invalid under contract v1. An empty selection should cancel/clear relevant query results and retain its distinct UI message.
- Boundary selection requires a caller-owned explicit level/vintage `boundaryFilter`. Rent/Census require a validated `areaFilter`, statistical-period controls and later-story acceptance. This task does not invent these values or implement those workflows.
- Per-topic defaults are user intent metadata, independent of the catalog's global initial `defaultEnabled` flags or source publication. A selected anomaly/event/disruption toggle does not certify producer/publication readiness.
- The panel's catalog availability describes source evidence. Current viewport/time results, freshness, loading/errors and retry belong to the shared result/status components and later integration.
- UI controls use Material widgets with labels and standard keyboard/semantics behavior. Browser Maps overlay interception, surface layout and full keyboard acceptance belong to the map surface/integration tasks.
