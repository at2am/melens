## Backend interface

`createAnomalyLayerLoader({producer?,resolveArea?}={})` returns the existing `ViewportLayerLoader(request, layerId, coverage, execution)` and only accepts `layerId='anomaly'`. Its default has no producer and returns an unavailable result with no items, unknown coverage/freshness, null totals/windows and no invented sources. It does not call BigQuery, a detector, an upstream endpoint or AI.

`VerifiedAnomalyProducer.read(request, execution)` is an explicitly injected trusted server dependency. `execution` carries the existing `signal`, `rowLimit` and `resultBudgetBytes`. The producer must honor cancellation, enforce its own bounded query deadline and return the internal `VerifiedAnomalyBatch` shape. This interface is not exposed for HTTP clients to submit results:

```ts
{
  verification: 'verifiedPublic',
  dataMode: 'live',
  queryIdentity: normalizedViewportIdentity(request),
  publicationProofs: [{sourceId, publishedBatchId, publishedAt}],
  records: [{
    item: AnomalyItem,
    evidence: {
      resultId, observationId, baselineDefinitionId,
      observationWindow, baselineAppliesToWindow, sourceIds
    }
  }],
  completeness: 'complete' | 'partial',
  totalMatching: number | null,
  unresolvedCount: number | null
}
```

The ordinary frozen v1 `AnomalyItem` supplies result, sensor, observation, baseline definition, evaluation window, observed/baseline values, delta, direction, eligibility, classification and public sources. Evidence IDs and sources must match that item. Observation and baseline application windows must equal the result window at microsecond precision; a baseline's `baselineAppliesToWindow` is the evaluation window for which the supplied definition/value applies, not an invented historical training window. The baseline definition and its public provenance are supplied by the producer. No threshold, comparison population, historical coverage or causal explanation is inferred.

`consumeVerifiedAnomalyBatch(value,{request,coverage,rowLimit,resultBudgetBytes})` validates the boundary and returns `ConsumedAnomalyBatch`: a normal `PublishedItemBatch<AnomalyItem>` plus `completeness`, `totalMatching`, `verifiedUnresolvedCount` and `publicationSourceIds`. Complete `totalMatching` must equal the located records returned; a bounded truncation must be partial with a null exact total. Null geometry stays in `unlocatedItems` and never gets synthesized coordinates. The loader returns only located rows and does not implement the separate anomaly unlocated endpoint.

The parser rejects sample/unverified envelopes, wrong viewport/mode/time identity, invalid/duplicate results, missing required classified observations/baselines, mismatched evidence or evaluation windows, a window ending after its producer publication, out-of-request sensor points, prediction assertions and withdrawn items. It checks every publication proof against T011's current admitted/published metadata; changed, missing or denied sources fail with safe `MapQueryError('notAvailable')`. Every item source needs a public version reference and the item must cite an anomaly publication. Malformed output/unknown reader errors become canonical `serviceUnavailable`; byte/row overruns become `budgetExceeded`. Private extra item properties are stripped by the frozen contract, while the internal evidence envelope is strict.

The consumer copies all supplied numerical, directional and eligibility values. It does not recalculate the delta or infer classifications, even from a visible count difference. Unclassified unknown values stay null. T011's finalization policy is reused; an empty successful producer read remains unknown unless complete spatial/time coverage, publication proof for all contributing anomaly sources and explicit zero unresolved/matching counts establish `noMatching`. No default area resolver is fabricated.

`anomalyCatalogAssessment({coverage,producerConfigured})` returns a normal `LayerCoverageAssessment`. `producerConfigured=false` forces unavailable with unknown coverage/freshness regardless of registry metadata. The integrator must use this policy for the catalog as well as the viewport. A registered source alone cannot advertise a connected producer.

T014's frozen integration hook is `loadAnomalyLayer?: ViewportLayerLoader` on `createMapService`. Default absent injection remains unavailable. Catalog availability additionally requires an explicit `anomalyProducerConfigured=true`, a loader and `checkPublicRecords`; T014's wrapper otherwise forces the honest unavailable descriptor. A future real producer must be paired with a trusted record-level public-rights checker through T014's `checkPublicRecords` composition; source watermarks alone cannot prove that individual anomaly records remain public. There is no approved anomaly view or real independent verifier in this checkout. No fake rights checker is supplied by T018.

## Flutter interface and integration

`AnomalyDetailsSection({required AnomalyMapItem item})` is a standalone `ConsumerWidget`. It displays the supplied sensor/result/observation IDs, exact baseline definition/value, observed value and delta, observation window with seconds/microseconds in Melbourne time, and explicit direction/eligibility/classification labels. Null values are Unknown; measured zero stays zero; unclassified never becomes not anomalous. A directly supplied withdrawn item suppresses all result facts.

Use T016's replacement hook, after T017 releases shared screen ownership:

```dart
typedDetailsBuilder: (item) => switch (item) {
  AnomalyMapItem() => AnomalyDetailsSection(item: item),
  _ => null,
},
```

`MapDetails` continues to supply the existing `MapItemProvenance`, source links, original public version references, source clocks, sample and historical labels. Avoid appending the widget after the old generic anomaly facts, which would duplicate baseline/delta/window fields. The widget explicitly says a baseline difference does not establish a cause. It has no Analyse action or AI call; the wider UC-04 workflow belongs to its own workstream.

The integrator merges the eleven English keys and metadata in `t018.l10n.json` into the shared ARB and runs the shared localization generator. T018 does not edit or generate shared localization files.
