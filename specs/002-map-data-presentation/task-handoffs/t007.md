## Limits and source boundary

Only project-qualified views in the literal `melens_query` dataset are referenced: `v_geo_records_current`, `v_geo_records_history`, `v_pedestrian_observations`, `v_boundaries`, `v_area_indicators`, `v_source_coverage`. Config rejects a raw/staging/ingestion dataset, unsafe project identifiers, unlimited/invalid limits and ceilings above 1,000 page items or 2 MiB response bytes. No caller SQL or identifiers enter query text. SQL identifiers and topic mappings are fixed; scalar values use typed BigQuery parameters.

Default scan ceilings are 100,000,000 bytes for current dynamics and 500,000,000 bytes for historical/statistical reads. Every execution first checks a bounded dry run, and the actual job also receives `maximumBytesBilled`, `jobTimeoutMs`, explicit stable ordering and a page-size-plus-one lookahead limit. Manual SDK pagination prevents unbounded automatic fetches. The client wait has an independent deadline; cancellation is bounded and best effort. A late-created job is cancelled too. Server-side query timeout is additional protection, not a claim that BigQuery always stops at that exact millisecond.

The default row JSON budget reserves 64 KiB below the 2 MiB response ceiling. Future viewport services must allocate the remaining byte budget across layers and measure the final adapted envelope; individual bounded query results alone do not prove a multi-layer response fits.

Complete queried rows expose an exact count for that fixed query scope. Lookahead, oversized geometry or SDK page truncation returns `kind=partial`, `totalMatching=null` and a bounded row prefix, including an empty partial prefix when the first record cannot fit. This never implies verified coverage or `noMatching`; those need T011/T014 evidence separately.

## Time, geography and remaining joins

- Current planning uses the admitted current source snapshot plus geometry bounds. It does not hide projects merely because they lack an exact observation timestamp, or fabricate a timestamp from fetch time.
- Current road/transit reads include unknown-start facts with explicit null times; a known end still constrains the interval. Historical temporal matches exclude fully unknown times. The disruption query covers both `road_disruption` and `transport` topics.
- Pedestrian spatial membership uses the view's observation-effective location; unlocated/ambiguous rows do not receive guessed points. Unlocated list/count reads belong to T013/T014.
- Boundary requests select one enumerated level/vintage mapped to actual published scheme names.
- Statistical period filters compare source date-only boundaries through `DATE(period_start/end)` with DATE parameters. A trusted injected indicator-selection validator must approve period ID/date/definition/property encoding before an indicator query can run. The view has no `property_type` column; unsupported selections return `notAvailable`, rather than silently dropping that criterion. T033 owns the future registry/lookup.
- Public cursor/snapshot requests return `cursorMismatch` in this low-level first-page runner. T014 must resolve frozen snapshots into immutable bounded pages; this runner must not re-query mutable views using an old public cursor. No BigQuery job ID or page token is exposed in the DTO.

T004 documents ADC and the deployment identity restriction: BigQuery job permission plus viewer access only to approved authorized views, with no ingestion/raw data or ingestion-write grants. This code does not alter or attest deployed IAM. Root/integrator will record real authorized-view dry runs separately; local injected tests establish the execution safeguards, not source readiness or live P0 acceptance.
