# T009: Shared map status, provenance and provider wiring

**Date**: 2026-10-01
**Status**: Implemented and validated as shared client foundation. Root completed the shared Riverpod/model/localization generation pass.

## Changes

- Added annotated `mapRepositoryProvider`, `mapLayerCatalogProvider`, `mapViewportProvider`, `mapItemProvider`, `mapUnlocatedProvider` and `mapAggregateMembersProvider`. The repository selection reads the explicit build configuration. Development sample mode creates `SampleMapRepository`; live mode creates `HttpMapRepository` using the app-owned HTTP client. There is no live-to-sample fallback or second HTTP-client owner.
- Each asynchronous request owns a cancellation handle cancelled when its provider is disposed. Automatic provider retries are disabled; a manual retry or scheduled refresh can invalidate the appropriate provider while preserving caller-owned filters/selection.
- Added `MapLayerStatus` for initial loading, refreshing, client errors and all five service evidence states. Retained values preserve their original source update and observation times. A retryable repository exception can expose the localized retry control; raw exception bodies are never displayed.
- `noMatching` is accepted only with complete results, a zero exact total, no unresolved items or cursor, and verified area/time coverage with public evidence. An empty `available` list is not reclassified. Freshness, completeness and full matching totals remain separate; unknown totals are never replaced by page length.
- Added `MapDataModeLabel`, `MapMeasuredCount` and `MapItemProvenance`. Sample data and predictions have visible text labels; counts distinguish null from measured zero. Dates use `MelbourneClock` for the original instant's Melbourne timezone, rather than the device timezone or today's offset. Statistical periods and unresolved source clock text remain unconverted. Public source attributions/versions are readable, with safe HTTP(S) source actions supplied by the caller.
- Added English ARB strings with descriptions and typed placeholders. All widgets use `material_ui` and theme colours.

## Integration handoff

- The map screen is deliberately unchanged. T015 and later story tasks consume these components and providers. A map surface must pass the response's original `mode`/`dataMode` to status/provenance widgets, including retained responses after refresh failures.
- `MapItemProvenance.onOpenSource` delegates opening a validated public URL to the eventual map/details surface; without a callback the public URL remains selectable text. No new URL-opening package was introduced.
- Query-family arguments are typed DTO objects; callers should retain the query object for a given request and change/invalidate it deliberately. Latest-request selection/filter protection remains T017's controller responsibility.
- T003's Web SDK loader is separate from the repository and does not run from this foundation. T015 must keep one loader in a provider and await authorized SDK readiness before constructing the map.
- These are client foundation changes. No production source admission, map UI acceptance, deployment or cloud mutation was performed.
