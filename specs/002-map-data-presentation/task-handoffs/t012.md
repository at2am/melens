## Owned files and frozen interfaces

- `cloud/map/src/query/adapter-common.ts`: safe pure public-record conversion helpers, `MapAdapterError`, `PublicSourceReference`, `PublicSourceResolver`, `PublishedItemBatch` and `publishedGeoRowSchema`.
- `cloud/map/src/query/planning.ts`: `adaptPlanningRow(row, {source, mode?})` and `adaptPlanningRows(rows, {resolveSource, mode?})`.
- `cloud/map/src/query/boundaries.ts`: `adaptBoundaryRow(row, {selection, source})` and `adaptBoundaryRows(rows, {selection, resolveSource})`.
- `cloud/map/test/planning-boundaries.test.ts`: dedicated behavioral validation.

Rows are `ViewRow` from the bounded fixed-query runner. `source` is an explicitly supplied public `SourceReference`; its ID must equal the row's source ID. The trusted resolver has signature `(sourceId: string) => PublicSourceReference | null`. T014 must first use T011's `findPublicSource(snapshot, sourceId)` to establish current public admission/publication, then supply original public metadata or an explicit source reference. A denied/missing/mismatched resolver result raises `MapAdapterError('notPublic')`. Attribution and URLs are never invented by the adapter.

`PublishedItemBatch<T>` has `items` (drawable), `unlocatedItems` (geometry null), `sourceIds`, and `unresolvedCount: null`. It supplies no completeness, geographic matching total, coverage or layer state. T014 combines it with the runner's exact/partial result and T011's query-specific coverage assessment. Any scoped unresolved count requires independent area/jurisdiction evidence; null geometry does not establish viewport membership. Empty conversion cannot produce `noMatching` or an inferred unresolved zero.

Batch ordering uses the contract's codepoint order for layer/id/version. Duplicate identity/version raises a safe error instead of silently changing counts. Malformed records fail the layer; adapters never discard bad rows while retaining a misleading exact count. `MapAdapterError` messages contain no input, provider payload, SQL or SDK diagnostics.

## Public record and geography behavior

Planning preserves `geo_record_id`, `version_id`, published geometry, title, summary, assertion kind, lifecycle and public original URL. Source reference `versionRef` follows the published row version. Current mode (default) rejects cancelled/resolved/withdrawn rows; historical mode retains their lifecycle. Fixed queries remain responsible for temporal/source-snapshot membership.

The planning view has no structured project-status or permit columns. `details.projectStatus` and `permitId` therefore stay null. The original source summary retains distinct development status/application information; the adapter does not reinterpret lifecycle as approval or extract supposed structured facts from prose/private payloads. Extra provider/ingest fields, batch/raw URIs, private credentials, and extra permit/status fields are excluded from the public item.

Boundary conversion accepts only the explicitly requested level/vintage, using the frozen ASGS/CLUE/municipal scheme mapping. ID must match the published `scheme:code:vintage` identity. Only legitimate Polygon/MultiPolygon geometry survives; points, null geometry, open rings, unsupported collection types and out-of-range/reversed coordinates fail. The adapter preserves the source polygon without simplifying, creating centroids, swapping coordinates or joining another vintage. `details.boundaryId`, name, level and vintage remain explicit. The view lacks original URL, so the supplied public source reference owns that link.

## Time and shared helpers

All item-time fields are present and nullable. Unknown observed/reported/effective clocks remain null even when `fetched_at` is known. Fetch time is never used as observation, publication or an invented effective instant. Boundary vintage is a period label rather than an inferred UTC timestamp. Optional published `source_time_text`, `source_timezone` and `period_label` are preserved when supplied; current fixed views do not expose source-local original clock text, so absent text stays null.

Known UTC instants are validated with seconds, literal `Z`, a valid calendar/clock and up to six fractional digits. Offsets/local clocks and finer precision are rejected. `comparePublishedInstants` and `offsetPublishedInstant` use exact integer microseconds, including pre-1970 times, so pedestrian full-window location checks can reuse them without millisecond rounding. Shared geometry/location helpers enforce evidenced source coordinates/official joins, reject unverified or area-derived precise points, and keep null geometry unlocated.
