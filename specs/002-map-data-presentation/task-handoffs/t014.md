## Transport and runtime

The frozen wire requests are unchanged: `GET /v1/map/layers`, `POST /v1/map/viewport`, `GET /v1/map/items/{encodedId}?requestId=&snapshotId=`, `GET /v1/map/unlocated?query={encoded JSON}`, and `GET /v1/map/aggregates/{encodedId}/members?requestId=&snapshotId=&cursor?&pageSize?`. Details/members preserve the original snapshot mode/window/filters. Extra and duplicate GET parameters are rejected; request-side sample switches cannot pass validation.

`startMapServer` uses validated existing MAP_* query configuration, `PORT` (default8080), host0.0.0.0, exact comma-separated `MAP_ALLOWED_ORIGINS`, and a bounded JSON array at `MAP_PUBLIC_SOURCES_FILE`. Missing public-reference registry denies item publication. Registry entries use the existing SourceReference schema; source admission must also be current/published. Item URLs/attributions come from reviewed registry metadata, never provider-row URLs. Startup errors log only safe event names.

Requests are bounded to256KiB; uncompressed replies to2MiB and1000 items across the viewport. Query row budgets are shared across selected layers and queries execute sequentially. HTTP allows8 active requests and30s total by default, propagates cancellation, and returns safe schema errors including malformed/oversized chunked bodies and header failures. Exact configured origins receive CORS; unknown origins fail. Replies use no-store.

The existing default scan ceilings remain100MB dynamic and500MB historical/statistical. Root's approved measured400MB development setting is runtime configuration only.

## Snapshot and count semantics

Snapshot TTL is exactly5min; defaults are32 active snapshots,16MiB total payload/cursor memory, and4096 cursors. Capacity fails with429. Unknown tokens/family/layer/context/member mismatches return400; retained expired snapshot ids return409. Bounded expired-id tombstones avoid unbounded memory. Tokens are random32-character base64url values with no data or credentials.

Loaded source rows are stored immutably; cursor reads never replace stored page content with a newly queried result. Snapshot context retains unused filters and normalized microsecond instants. Whole-envelope item/byte budgets can produce stored-page continuations. Upstream row/byte/page truncation always keeps totalMatching=null, and the final stored-buffer page has no invented continuation into unqueried rows. Exact totals are published only after complete successful conversion. Unresolved viewport counts remainnull without an independent scope proof. No bbox resolver means query-empty coverage staysunknown, nevernoMatching.

Unlocated queries require current admitted published source evidence for every requested area reference or an exact trusted source-jurisdiction label. Dedicated SQL requires null geometry or insufficient full-window pedestrian location validity and preserves that association. It never applies a viewport count to unlocated rows or guesses coordinates. Pedestrian areaRefs lists are denied because the observation view does not expose row-level area associations. Multi-layer unlocated first pages with omitted stored rows remainpartial without an ambiguous single-layer cursor; clients can request a specific layer.

## Current public eligibility, including retraction

Every successful stored-record read checks current source admission/publication watermarks and current record eligibility. A changed watermark invalidates the snapshot rather than mixing versions. Fixed `publicRecords` queries only prove current rights for stored identities; replies still use immutable stored objects.

Geo proofs use native geo_record_id/version_id/source_id in approved current/history views. Those views independently check latest record public_query_allowed and rights_status, so record-level withdrawal is denied even if the source watermark is unchanged. Boundary proofs use native boundary_id/version_id/source_id. Pedestrian proofs use source_id/sensor_id/observed_at then require the exact deterministic adapted content version and full item. Redaction/content mutation with unchanged version is denied as well. Proof comparison is linear in the bounded stored rows.

**Additional fail-closed gate discovered during production SQL inspection:** existing `v_boundaries` filters source-record rights before choosing the latest eligible version, allowing an older eligible version to survive a later ineligible revision. Existing `v_pedestrian_observations` joins source_records but does not check those records' rights_status/record_status. Consequently T014 requires a trusted supplemental current record-rights checker for boundary/pedestrian and defaults those loaders to unavailable without it. No cloud/data repair was performed in this lane. Merely seeing a current source batch does not unlock these families.

`createMapService` option `checkPublicRecords?: SnapshotAccess['checkPublicRecords']` supplements built-in ordinary proof for boundary/pedestrian and externally produced item families. Signature is `(items: readonly MapItem[], snapshot: StoredSnapshot, coverage: SourceCoverageSnapshot, execution: {signal?: AbortSignal}) => Promise<boolean>`. Missing proof denies real records. Future anomaly production additionally requires `loadAnomalyLayer`, explicit `anomalyProducerConfigured=true`, and the trusted checker; absent producer staysunavailable even if catalog source metadata appears.
