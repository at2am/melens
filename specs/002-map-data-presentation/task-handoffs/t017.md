## Frozen controller API

`viewportControllerProvider` exposes `ViewportState`. Desired mode/window/layers/bbox/actual zoom stay separate from `response` and `responseQuery`, the original successful query. Other fields/getters are dataMode, isLoading, isOutsideService, isCameraMoving, safe typed error, blockedLayers, queryableLayers, canQuery, canRetry, hasPartialResults and matchesResponseWindow.

Notifier methods are setLayers, setRegion, useServiceBounds, setWindow, setBoundaryFilter, setAreaFilter, cameraMoving, refresh and retry. Layer/region/window changes debounce for250ms by default. Superseded work cancels immediately before debounce. Completions require the latest generation and matching requestId/mode/dataMode/layers. Camera motion cancels work before the next visible-region read completes and blocks queries until idle; an identical region can restart a cancelled operation. Disposal cancels the timer and request.

`boundedViewportRegion` intersects actual visible bounds with the frozen operational envelope `[144,-39,146.5,-37]`. Completely outside views skip requests without inferring source coverage. Zoom must be finite and0–22; pageSize is1000. Dynamic windows are UTC, increasing, half-open and at most31days. Empty selected layers skip network and clear results. Boundary/area layers without approved required filters remain visibly blocked; no level/vintage/indicator metadata is invented.

Partial layers retain unknown exact totals and original observation windows. Failed refreshes retain the successful response/query, mode, data mode and source dates, show safe failure text and allow manual retry. There is no automatic retry loop or live-to-sample fallback. Unknown exceptions become safe contract failures.

## Screen integration

The screen joins T010 LayerPanel, T015 MapSurface, T016 selection/details/unlocated widgets and T023 aggregate render/details hooks. City activity is the only selectable P0 topic. Desktop has a scrolling layer/status sidebar; narrow screens use a pointer-intercepted drawer and status sheet. The existing details layout supplies side/bottom panels. Layer coverage/freshness/completeness stays distinct from client loading/failure.

Current mode uses the clock's last15 completed minutes. Historical controls provide1hour,24hours,7days and31days, plus previous/next windows; next stops at now. Labels use melbourneClockProvider and Australia/Melbourne including DST. Displayed intervals state that the end is excluded. Retained responses announce their original query window.

GoogleMapController.getVisibleRegion runs after map creation and camera idle, with an independent stale-read generation guard. Toggles issue no camera reset. MapScreen test/integration seams are mapBuilder, visibleRegionReader (`Future<MapBounds> Function()`), onZoomToBounds and approvedUnlocatedScope.

Until a base map is available, catalog.serviceBounds can supply a bounded keyboard-accessible object list, explicitly labelled query-service scope rather than visible map/source coverage. Missing Maps credentials remain explicit. The screen captures a selected response's original time/filter context, so a later successful time query cannot silently restore an excluded old selection. Offscreen/removed/withdrawn handling remains T016/T024's controller behavior. Aggregate highlights require actual memberIds through aggregateRepresentsSelection, never proximity.

Unlocated entry needs caller-supplied admitted scope or verified catalog area identifiers plus source evidence. It never guesses jurisdiction or bbox membership. Its detail selection uses its own returned list snapshot. Unsupported association evidence remains unavailable or a truthful service error. Aggregate rendering/details hooks are wired; T025 owns the final server zoom join and explicit expired-member snapshot rebinding.
