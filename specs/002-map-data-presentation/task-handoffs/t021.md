# T021: Nominal zoom bands and hysteresis

**Date**: 2026-10-01. **Owner**: p0_t021_zoom. **Status**: Implemented and validated as pure zoom-policy foundation.

## Files and interface

- `app/lib/features/map/state/zoom_policy.dart` defines `ZoomBand.overview`, `district`, `neighbourhood` and `closeUp`, ordered from widest to closest view.
- `ZoomPolicy.nominalBand(double zoom)` classifies the initial view: `[0,11)`, `[11,14)`, `[14,17)` and `[17,22]`.
- `ZoomPolicy.bandFor(double zoom, {ZoomBand? previousBand})` uses nominal classification when no previous band is supplied. Otherwise, it moves closer only above boundary + 0.2, and farther only below boundary - 0.2. Equality retains the band. Each crossed boundary is checked, so a single camera update can jump across multiple bands.
- Public constants are `minimumZoom=0`, `maximumZoom=22` and `hysteresis=0.2`. Both entry points throw `ArgumentError` for nonfinite or out-of-range zoom; values are never silently clamped.
- `app/test/features/map/state/zoom_policy_foundation_test.dart` owns this task's foundation tests. The later T026 `zoom_policy_test.dart` remains separate.

## Integration

The policy has no Flutter, Maps, Riverpod or model dependencies and stores no mutable state. A camera/controller caller retains the returned `ZoomBand` and passes it as `previousBand` on the next update; it uses nominal classification only when opening or deliberately resetting the map. Consumers may use the typed band for both rendering and query-envelope decisions. A hysteretic band can differ from the raw zoom's nominal band near a boundary, so recomputing the nominal band on each update would discard the required buffer.

The policy controls presentation granularity only. It never changes geometry, member identity, statistical geography or selection. A closer band still permits dense/same-location aggregation; source precision and statistical boundaries remain authoritative. T023 owns grouping display and member actions, T024 owns selection continuity, and T025 connects the settled band to server responses. The Dart names are internal; any differing server-side band labels require an explicit integration mapping without changing the frozen v1 wire contract.

The frozen interface was sent to root and the T023 worker (`prep_t007_queries`). No annotated provider, shared contract, localization, package, generated file or task-status edit was introduced.
