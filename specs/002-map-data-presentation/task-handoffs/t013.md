# T013 — pedestrian, disruption and event published-row adapters

Implemented and locally verified on 2026-10-01. This handoff covers typed row and batch adaptation; T014 owns runner calls, coverage/result state assembly, HTTP, snapshots and scoped unlocated queries.

## Files and frozen interface

- `cloud/map/src/query/pedestrian.ts`: `adaptPedestrianRow(row, { source, locationSource? })`; `adaptPedestrianRows(rows, { resolveSource, mode })`.
- `cloud/map/src/query/disruptions.ts`: `adaptDisruptionRow(row, { source, mode?, asOf? })`; `adaptDisruptionRows(rows, { resolveSource, mode, asOf? })`.
- `cloud/map/src/query/events.ts`: `adaptEventRow(row, { source, mode?, asOf? })`; `adaptEventRows(rows, { resolveSource, mode, asOf? })`.
- `cloud/map/test/dynamic-adapters.test.ts`: 20 behavioral acceptance tests.

Input rows are `ViewRow`, matching the fixed query projections. Row output types are `PedestrianItem`, `DisruptionItem` and `EventItem`, all validated with the public `mapItemSchema`. Batch results use T012's `PublishedItemBatch<T>`: ordered located `items`, ordered null-geometry `unlocatedItems`, distinct `sourceIds`, and `unresolvedCount: null`. Batch adaptation does not claim coverage, a full count or a successful query.

`resolveSource: PublicSourceResolver` must combine T011 `findPublicSource(snapshot, sourceId)` with explicit public attribution metadata. A denied, absent or unpublished source resolves to null and throws safe `MapAdapterError('notPublic')`; T014 returns the layer unavailable. Pedestrian rows additionally require admission for every non-null `location_source_id`. Do not manufacture a SourceReference, published batch, candidate admission or measured count when this fails. Every successful detail/continuation/list read must still recheck admission in T014.

`mode='current'` rejects cancelled/resolved/withdrawn geo rows rather than silently removing them and retaining an incorrect total. Historical adapters preserve these lifecycle states. For current event/disruption reads, T014 should pass `asOf=generatedAt`: an active source record with known future validity is represented as planned. No request/fetch clock is copied into an unknown source-time field.

## Preserved semantics

Pedestrian counts retain null versus measured zero and minute versus hour granularity. Their half-open count windows preserve microseconds. The adapter uses the coordinates projected by the published observation view; it never uses a current-location lookup or centroid. Ambiguous, inactive and unlocated locations remain null geometry. A location that covers only the observation start but ends before the whole count window is also unlocated.

Road LineString/MultiLineString and area extents retain their real geometry and become affected extents. A real road point remains a point without being labelled a road segment. An officially joined transit stop remains a stop point. Route-only/unmapped alerts remain unlocated. The currently projected selectors contain IDs rather than verified service names, so `serviceNames=[]` is intentional. No speed/congestion measurement is inferred from a disruption.

Structured road/GTFS summaries expose only description, impact fields and the planned recurrence caveat. Full `source_properties`, selector bodies and unrelated provider payloads are omitted. Original road clock text remains in `sourceTimeText`; undocumented offsetless unplanned-road clocks have no fabricated timezone or UTC instant. Planned road timezone remains `Australia/Melbourne` when the published summary supplies it. Missing observed/published clocks remain null, independently of fetchedAt.

Event planned/cancelled/retired states are preserved. Ticketmaster venue and original local-clock text are extracted from the actual normalizer's public summary string; category remains null because the projected row does not provide it. The current Ticketmaster normalizer writes `valid_to=valid_from` when no positive end is supplied; this documented connector sentinel becomes `endAt=null` and `time.validTo=null`, retaining the known start. Other reversed/empty intervals fail safely.

## Identity and upstream projection limitations

Generic geo items preserve their published `geo_record_id` and `version_id`. The pedestrian view does not project native observation or location version IDs. Pedestrian item IDs are deterministic SHA-256 identifiers of source, sensor and normalized observed UTC instant. Public versions hash the selected published batch and public count/location content. This is a version of the projected observation content, not a claim about an unavailable upstream version. Location provenance uses its admitted source attribution with `versionRef=null`; the latest location batch is never labelled as the historical coordinate version.

The underlying SQL and normalizers were inspected read-only: `cloud/data/sql/002_core_views.sql`, `004_street_views.sql`, `007_changes_views.sql`, the pedestrian normalization/connectors, the road connectors, GTFS alerts and Ticketmaster normalizer. No feature001/data/publication/source metadata was modified.

## T014 integration requirements

The original fixed viewport query selects only spatially located rows. Its empty rows cannot establish zero relevant unlocated records. Keep `unresolvedCount=null` until an independently complete approved area/jurisdiction-scoped unlocated query establishes the exact association count. Scope membership must come from accepted source/area evidence, never the operational Melbourne bbox or an arbitrary broad source query.

The pedestrian view joins coordinates at observation start, while the public contract requires validity throughout the minute/hour window. T014 was notified to add fixed drawable predicates for full-window validity and the complementary unlocated predicate. A batch can still return `unlocatedItems` from rows originally selected by a located SQL query; do not reuse that SQL row total as an unchanged geographic total. Either account for all excluded rows in a complete query or return totalMatching=null. Null items must use the scoped list and remain outside viewport items/totals.

Source-clock arrays (for example multiple GTFS active/impact periods) are not projected as a dedicated public interval structure. The adapters preserve the currently published validity fields and do not claim more granular schedule coverage. Source readiness, publication acceptance, scope association and real GCP query behavior remain external evidence obligations.
