## 3. 有界核查与关键行为验证 (Bounded Verification)

### 3.1 时间字段与夏令时 (DST) 校验
- 官方接口的 `sensing_datetime` 带有显式时区偏移（`+00:00`），无本地时区的模糊小时（Ambiguous Hour）或跳变小时（Nonexistent Hour）。
- 连接器通过 `validateMelbourneSensingDateTime` 函数验证：在标准时间（AEST, UTC+10）与夏令时（AEDT, UTC+11）下，上游伴随的 `sensing_date` 与 `sensing_time` 必须与 UTC 时间戳在墨尔本本地时间一致。
- 无时区偏移或格式非法的输入将在 Zod 解析阶段 fail closed（报 `schema_changed`）。

### 3.2 真实分钟窗与 15 分钟重叠拉取
- 实测执行真实采集窗口 `[2026-09-30T12:05:00.000Z, 2026-09-30T12:20:00.000Z)`：
  - 自动向前推算 15 分钟重叠起点：`2026-09-30T11:50:00.000Z`
  - 实际拉取记录数：`1,040` 条
  - 成功转换 `sourceRecords`: `1,040` 条，`pedestrianObservations`: `1,040` 条
  - 采集结果完整性：`expected_records: 1040, fetched_records: 1040, expected_pages: 11, fetched_pages: 11, complete: true`
  - 数据版本标记：`sourceRevision: "2026-09-30T12:25:00.000Z"`

### 3.3 缺分钟与缺测保持 null / 缺口（严禁补零）
- 官方数据特性：若传感器在该分钟无行人经过，上游不生成行。
- 连接器严格保持物理缺口，绝不在缺失分钟生成 0 计数的虚构记录。
- 上游若出现 `direction_1: null, direction_2: null, total_of_directions: null`，在 `PedestrianObservation` 中对应计数字段严格保持 `null`，不补 0。

### 3.4 重复记录与冲突处理
- 官方已知公告指出部分传感器（如 67/68/69）历史上偶发瞬时重复行。
- 连接器使用 `sensor_id + observed_at` 作为唯一逻辑键，并结合内容哈希：
  - 完全相同的重复行直接幂等去重（`continue`），不报错；
  - 若相同键出现计数值冲突（如不同的 direction/total），严格 fail-closed 退出并报 `validation_failed: Conflicting duplicate sensor-minute readings`。
- 方向数算术一致性：若 `direction_1 + direction_2 !== total_of_directions`，报错 `validation_failed: Upstream direction counts conflict with total`。

### 3.5 边界失效与过期窗口阻断
- 当请求窗口起点（含 15 分钟重叠）早于最新记录前 1 小时（如请求 2 小时前的窗口）时，连接器阻断并返回 `incomplete_window: Requested minutes have expired from the past-hour feed`。
- 当请求窗口起点在未来时，连接器返回 `incomplete_window: Requested window is in the future relative to upstream feed`。

### 3.6 R04 (P1) 修正：上游可用分钟边界判定与防漏取保护
- **缺陷分析**：之前版本仅检查 `window.from` 是否晚于 `latestObservedAt`，当 `from <= latest < to` 时（如上游最新为 12:30，请求 `[12:15, 13:00)`），若返回 success 并将 `checkpointAfter` 推进至 13:00，会导致上游延迟到达的 12:31..13:00 读数被永久漏取。
- **修正实现**：
  1. 计算上游最新完整可用分钟边界：`upstreamLatestAvailableMs = latestObservedMs + 60_000`（因 `sensing_datetime` 标定该分钟起始，如 12:30 记录覆盖 `[12:30, 12:31)`）。
  2. 当 `input.window.to > upstreamLatestAvailableMs` 时：
     - 默认模式：fail closed 返回 `incomplete_window: Requested window end exceeds latest upstream available minute`，绝不推进超过上游最新时间的 checkpoint。
     - 渐进安全模式（`clampToAvailable: true`）：将采集窗口截断至 `upstreamLatestAvailable`，并将 `checkpointAfter` 严格设置为该安全边界，下轮采集无缝接续。
  3. 补充 3 组完整测试用例：
     - `from <= latest < to`：拒绝推进并返回 `incomplete_window`；
     - 上游延迟超过 15 分钟：分别核查全在未来及尾部越界场景，均 fail-closed 拦截；
     - 连续两次采集：验证重试流程与渐进安全模式，两次采集无重复、无遗漏、缺分钟不补零、null 字段严格保留 null。
