## 4. 可重复的行为验证与核心不变量断言

连接器在设计与实现上保持了高标准的防御性契约与不变量保证：

### 4.1 真实调用失败关闭 (`Fails Closed`)，拒绝冒充
- 当调用真实官方 API 遇到 404 时，连接器捕获 `HttpFailure` 并输出明确的 `ConnectorFailure`（`kind: 'failure'`, `code: 'schema_changed'` 或 `upstream_unavailable`），`complete: false`，`fetched_records: 0`。
- 绝不因上游 404 而静默返回 0 条记录的成功结果；更绝不在实盘调用中回退使用本地测试 fixture 伪装采集成功。

### 4.2 缺失数据严禁补零 (`No Zero-Filling`)
- 若特定时间间隔或某一模式的计数缺失（如 upstream 返回 `null`、`-`、`<4`、`missing`），`parseCount()` 严格返回 `null`，并且 `status` 标记为 `'missing'`。
- 明确断言：未观测到数据表明观测中断或缺失，**绝不代表活动量为零 (0)**。真实的 0 计数（如步行街车辆计数为 0）则真实保留为 0。

### 4.3 模式细分严格保持独立 (`Modal Breakdown Preservation`)
- `vehicle_count`、`bicycle_count`、`pedestrian_count` 分别作为独立字段保存，禁止跨模式加总合并或混淆。

### 4.4 严格拒绝全城覆盖声明 (`No Universal Citywide Coverage Claim`)
- 产生的所有记录均标明 `is_citywide_coverage: false`，`coverage_scope: 'instrumented_corridor_only'`，并在 GeoRecord 的 `summary` 中显式注明免责声明。
- 仅在有确定物理经纬度时赋予 `location_role: 'sensor_site'`，无坐标时回退为 `unknown`，防止地图误渲染。

### 4.5 候选替代数据集自动化冲突断言
- 测试文件中专门建立了候选替代数据集与 T032 不变量的自动化检查，若未来有人试图将 `traffic-count-vehicle-classification-2014-2017` 作为替代，断言将因违反 5 分钟采样、缺少行人计数、缺乏持续更新流水而立即报错阻断。
