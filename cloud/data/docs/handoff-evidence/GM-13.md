## 1. 改动与新增文件清单

1. `cloud/data/src/connectors/vicmap_planning/index.ts`
   - **优化分批请求大小**：将 `CHUNK_SIZE` 由 20 调整为 100。在 ArcGIS REST 规范下，100 个整数 OBJECTID 构成的 URL 长度仅约 600 字符（远低于安全阈值 2048 字符），使 Melbourne LGA 2,327 条要素的 HTTP 往返请求次数由 117 次缩减至 24 次，采集效率提升近 5 倍。
   - **修复覆盖层图例代码（`scheme_code`）核查逻辑**：原实现错误地假定 overlay 图层的 `scheme_code` 必须等于 `'PO'`（误将 Parking Overlay 缩写当作整个覆盖层代号），导致真实线上维州规划覆盖层中除停车覆盖层外的 17 类覆盖层（如 Heritage Overlay `HO`、Design and Development Overlay `DDO`、Specific Controls Overlay `SCO` 等）被误判为图层不匹配。修复为维州官方规范不变式：
     - 分区图层（`layer.kind === 'zone'`）：`fields.scheme_code` 必须严格等于 `'ZN'`；
     - 覆盖层图层（`layer.kind === 'overlay'`）：`fields.scheme_code` 必须为覆盖层类型代码，严禁等于 `'ZN'`。
   - **保持严格失败关闭（Fail-Closed）**：若任一图层返回空 ID 列表（`objectIds: []`）、存在重复要素 ID、或分批数量不匹配，立即抛出异常并返回 `kind: 'failure', completeness: { complete: false }`，绝对禁止以单层冒充完整规划现状。

2. `cloud/data/test/connectors/vicmap-planning.test.ts`
   - **覆盖真实维州多样化覆盖层代码**：新增单元测试验证覆盖层支持 `HO`、`DDO`、`SCO`、`EAO`、`SBO`、`PAO`、`PO` 等各类法定图例代码，同时确保在覆盖层中出现 `'ZN'` 会触发异常阻断。
   - **复现并验证 E01 上游阻断行为**：新增 `EmptyZoneClient` 测试，精确模拟 2026-09-29 发生的分区图层（layer 3）返回 `objectIds: []` 的场景，断言连接器必须返回 `kind: 'failure'` 与 `completeness.complete = false`。
   - **覆盖覆盖层为空阻断**：新增 `EmptyOverlayClient` 测试，断言覆盖层为空时同样失败关闭。
   - **覆盖重复 ID 与分页不完整**：新增测试覆盖上游返回重复 OBJECTID、分批要素少于预期时的严格阻断。
   - 保持原有 11 个契约与规范化测试，测试总数由 11 项扩展至 16 项且全部通过。

## 3. E01 阻断复核与同机构正式替代服务调查结论

### 3.1 当前 ArcGIS Zone Layer 3 复测结论
- **原 E01 阻断成因**：在 2026-09-29 执行复测时，ArcGIS FeatureServer Layer 3 查询 `where=lga='MELBOURNE'&returnIdsOnly=true` 返回 `objectIds: []`（全层 `where=1=1` 同样为空）。这是维州规划局在云端对其规划分区底库进行全量维护、重新切片或数据迁移期间造成的暂时性上游空集。连接器当时按规则 fail-closed 退出属于绝对正确的防御行为。
- **2026-09-30 官方恢复事实**：官方编辑审计元数据表明，DTP 于 **`2026-09-30T03:39:32.817Z`** 完成了 Layer 3 的全量数据发布与重载。当前现场实测：
  - Layer 3 全维州共有 **51,245 个** 分区多边形要素；
  - Melbourne LGA 包含 **439 个** 分区要素（包含 Capital City Zone `CCZ1`、Public Park and Recreation Zone `PPRZ`、Public Use Zone `PUZ1`/`PUZ2`、Special Use Zone `SUZ`、Mixed Use Zone `MUZ` 等全部核心分区）；
  - Layer 2 Melbourne LGA 包含 **1,888 个** 覆盖层要素；
  - 两个图层均可正常查询、稳定返回、且各要素具有严格唯一的 OBJECTID 与 UFI。

### 3.2 同一官方机构的正式替代服务调查
对维州交通与规划厅（DTP）及 DataVic 平台提供的规划数据发布通道进行了详尽审计：
1. **正式在编 REST API 服务（本连接器对接服务）**：
   - DataVic 登记数据集：`vicmap-planning-api`。
   - 官方分配的正式 Esri REST FeatureServer 位于 `services-ap1.arcgis.com/P744lA0wf4LlBZ84/ArcGIS/rest/services/Vicmap_Planning/FeatureServer`。
   - 该服务是维州官方“Vicmap as a Service (VaaS)”体系中唯一支持按属性（LGA）、按对象 ID 列表有界切片分页拉取 GeoJSON 的在线服务。
2. **DataVic DataShare 批量 GIS 文件导出服务（非实时批量文件）**：
   - 包含数据集：`vicmap-planning-planning-scheme-zone-polygon`（DataShare ID: `e61471a1-277d-54ea-9a75-3cc9b1a86800`）与 `vicmap-planning-planning-scheme-overlay-polygon`（DataShare ID: `47847f20-b7ab-5cb9-8baf-c88ed6500988`）。
   - 该服务仅提供全维州 GB 级别的静态大文件打包下载（格式为 DWG/DXF/SHP/GDB/TAB），每月仅批量生成一次，不提供 REST 查询与 LGA 级有界增量拉取。
3. **核查结论**：
   - 当前配置的 ArcGIS FeatureServer 是维州 DTP 唯一的官方在线规划图层服务。
   - 目前该服务 Layer 2 与 Layer 3 **已全部恢复并处于最新版本在线状态**。
   - 连接器继续实施双层完整性核验：只有当 Zone 与 Overlay 均完整返回且版本在拉取前后保持一致时才标记 `complete: true`，绝不放宽校验门禁。
