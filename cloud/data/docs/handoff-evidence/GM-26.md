## 已接收的测试

测试实际调用 Ticketmaster、Transport Victoria、Vicmap 和开发项目 normalizer，以及 `joinGtfsAlertLocations` 与 `BigQueryPublisher`。本地 publisher 仍使用测试 double，不能证明 BigQuery 实际执行。

活动取消、改期、事故解除和迟到旧版本的内存选择断言可保留为合成契约样本。`queryViewCurrent`、`compareGeoRecordProvenance`、`canonicalGeoRecordComparator` 和 `selectLatestGeoRecord` 都在测试文件中定义，必须按本地模拟理解。对这些 helper 使用哈希排序、逆序时间、提前过滤等对照，证明的是样本可以区分不同模拟算法。改坏生产 SQL 不会自动改变这些 helper。

静态 GTFS 缺少官方 `feed_version`、仅有归档哈希或版本空白时，真实 `joinGtfsAlertLocations` 保持 `version_unverified`。带班次日期或开始时间的 selector 还需 calendar/frequency 证据。Root 的正向 fixture 保持 `tripStartDate = null`、`tripStartTime = null`。

原 Gemini 返工仍声称本地比较能证明生产排序变异失败，这一结论已撤回。
