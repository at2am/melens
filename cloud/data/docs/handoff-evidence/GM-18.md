## 3. 本地契约与核心逻辑实现

### 3.1 元数据与坐标最小化采集
- **严格限定字段**：严格遵循 `source.json` 的 `allowed_fields`，仅提取 `id`、`name`、`url`、`dates` 与 `_embedded.venues.location`。
- **正文防御**：即使上游 API 返回活动描述（description）、注意事项（info/pleaseNote）、票务促销（promoter/priceRanges）或图片（images），连接器不予提取，空间记录 `summary` 仅生成标准格式的元数据摘要（状态、本地起止、场馆名称），不爬取正文。
- **坐标解析**：
  - 当且仅当场馆包含经纬度且数值位于合法区间（`lon ∈ [-180, 180]`, `lat ∈ [-90, 90]`）时，生成 GeoJSON `Point`，赋予 `location_role: 'event_site'` 与 `location_confidence: 'source_coordinate'`；
  - 缺失场馆或坐标越界/异常时，安全降级为 `geometry_geojson: null`, `centroid_lon: null`, `centroid_lat: null`, `location_role: 'unknown'`, `location_confidence: 'unverified'`，完全符合 `validateGeoRecordGeography` 规范。

### 3.2 改期、延期与取消生命周期契约
- **取消（Cancelled）**：
  - 支持 `canceled` 与 `cancelled`（大小写不敏感）；
  - `SourceRecord.record_status = 'cancelled'`，`GeoRecord.record_status = 'cancelled'`；
  - 完整保留场馆坐标与排期信息作为历史事实，实体 ID（`source_record_id`、`geo_record_id`）保持不变，`version_id` 自动随状态更新；
  - 生产查询视图将排除已取消事件，全量时间线则呈现已取消状态。
- **延期（Postponed / TBD / TBA）**：
  - 若 `status === 'postponed'` 或 `dateTBA === true` 或 `dateTBD === true`，严格将 `valid_from` 与 `valid_to` 置为 `null`，绝不凭空臆造开始时间；
  - 摘要中明确标记 `postponed`，`record_status = 'planned'`。
- **改期（Rescheduled）**：
  - 更新至新起止时刻，保持稳定实体 ID，生成新版本哈希。

### 3.3 缓存撤除与公网查询阻断契约
- **冷存储拦截**：`retainableRawRecords: null`，连接器采集完成后不将原始报文落入 GCS 长期归档；
- **公网查询阻断**：所有空间记录的 `public_query_allowed` 统一硬编码为 `false`；`rights_status` 严格锁定为 `'review_required'`；
- **准入清单防护**：`source.json` 保持 `license_status = "review_required"` 与 `access_status = "candidate"`，声明 `staging_retention_days = 1`。

### 3.4 异常与分页健壮性
- **深分页超限拦截**：若时间窗口内活动总数超过 1,000 条，或者 `page * size >= 1000`，立即返回 `code: 'incomplete_window'`，防止因为 API 截断产生不完整窗口。
- **分页一致性断言**：跨页遍历时，前后页声明的 `totalElements` 或 `totalPages` 若发生变动，或最终拉取条数与总数不符，均触发 `incomplete_window`。
- **限流与服务故障映射**：捕获 HTTP 429 映射为 `rate_limited`（携带换算后的 `retryAfterSeconds` 秒数），HTTP 503 映射为 `upstream_unavailable`，HTTP 404/Schema 破坏映射为 `schema_changed`。

## 5. 仍阻断的门槛与后续建议

1. **凭据准入阻断（API Key Blocked）**：
   - Ticketmaster 官方端点强制要求合法 `apikey` 查询参数；
   - 代码严格禁止把测试 Key 写入仓库或环境变量中；
   - 依赖项目拥有者在 GCP Secret Manager 中存入 `ticketmaster_discovery_api_key`；在此之前，`access_status` 必须保持为 `'candidate'`。
2. **使用条款与缓存撤除阻断（Terms & Deletion Pipeline Blocked）**：
   - 官方条款严禁长期存储活动内容，并要求在权利人提出要求后 24 小时内删除；
   - 当前数仓的 BigQuery 历史记录尚无来源级的定时下架与自动擦除流水线；
   - 在建立经法律审核的保留策略与删除机制前，`license_status` 严格保持 `'review_required'`，空间记录的 `public_query_allowed` 严格保持 `false`。
3. **活动覆盖度门槛（SC-001 Blocked）**：
   - 因 Ticketmaster 处于准入阻断状态，且查询仅为以墨尔本市中心为圆心的大致 80km 范围、且仅包含 Ticketmaster 平台自身售票活动，无法证明整体城市活动覆盖度；
   - 维持 SC-001 门槛未达标状态，后续应继续评估合规开放替代来源（如 What's On Melbourne 等开放日历）。
