### 3.3 观测时间新鲜度与过期现状（重大业务发现）

对 6,324 条记录的 `status_timestamp` 相对核查时刻（2026-09-30 12:27 UTC）进行了时效性统计：
- **> 24 小时未更新**：**3,929 条 (62.13%)**
- **> 7 天未更新**：3,510 条 (55.50%)
- **> 30 天未更新**：3,254 条 (51.45%)
- **> 1 年未更新**：1,016 条 (16.07%)，最旧的一条停留在 2022-09-13
- **<= 24 小时内更新**：**2,395 条 (37.87%)**

> [!WARNING]
> **关键结论**：当前官方传感器快照中有超过 **62% 的传感器读数处于陈旧或失联状态**。大量读数停留在数月甚至数年前的传感器仍然标注为 `Unoccupied`。若消费者将 `occupied: false` 直接解读为“当前空位可停”，将导致严重的错误引导。因此：
> 1. `occupied: false` 仅代表**传感器硬件最后一次报告的物理空位状态**；
> 2. 必须保留准确的 `observed_at` 和 `source_updated_at`；
> 3. 消费端必须强制执行新鲜度窗口判断（如 `age <= 2 * cadenceSeconds`），超期必须标记为 `occupancy_stale`。

## 4. 可重复的行为验证与关联契约

1. **键缺失时保持未关联（Strict Unassociated Status）**：
   - 官方 API 未提供 `marker_id` 与 `bay_id` 时，`extractMarkerAndBayId()` 返回 `{ sensorKey: 'kerbside:...', markerId: null, bayId: null }`。
   - `ParkingObservation` 中的 `marker_id` 与 `bay_id` 严格置 `null`。
   - 车位规范匹配（`evaluateParkingBay`）因找不到匹配的 `marker_id`，会将观测标记为 `occupancy_missing`，`mayParkNow` 维持 `unknown`，绝对无法晋升为 `yes`。
2. **不能称空位可停（Never Assert Parking Permission from Sensor Alone）**：
   - 车位可停（`mayParkNow = 'yes'`）需要同时满足：
     1. 车位存在且有效（`bay.public_access === true && bayActive`）；
     2. 传感器观测新鲜且无冲突（`fresh && !tied`）；
     3. 真实车位编号与停车限制规则存在已验证的官方跨表交叉对照（`crosswalk !== null`）；
     4. 规则结论明确为允许（`conclusions[0] === 'allow'`）；
     5. 物理状态未被占用（`occupied === false`）。
   - 缺失 `marker_id` / `bay_id` 或规则交叉对照时，原因必定包含 `rule_crosswalk_unverified` 或 `occupancy_missing`，决策严格为 `unknown`。
3. **空值与异常防御**：
   - 纯空白或空字符串的 `kerbsideid` 无法通过 Zod Schema 解析，且在提取函数中立即抛出异常。
   - 缺失 `status_timestamp` 的数据行，`observed_at` 置 `null`，`time_missing_reason` 记录 `"Status timestamp absent upstream"`，且不生成 `ParkingObservation`，避免无时间序列破坏下游聚合。

## 6. 仍阻断的门槛与集成建议

1. **许可证复核门槛（T077 依赖）**：
   - 官方数据集声明使用 `CC BY 4.0`，目前 `source.json` 中保持 `license_status = "review_required"`。
   - 需由项目集成人员与法务人员复核 City of Melbourne 开放数据免责条款（Disclaimers & Outages）以及再分发/商业化合规要求，审核通过后方可变更为已批准状态。
2. **生产准入与发布门槛（T070 / T071 / T077）**：
   - 当前保持 `access_status = "candidate"`。
   - 未执行 GCP `--apply`，未发布 BigQuery，未在 Cloud Scheduler 启用周期性采集。
3. **传感器与车位限制（Restrictions）关联阻断（T035 / T037 / T039 依赖）**：
   - 官方传感器 API 完全不包含 `bay_id` 或 `marker_id`。
   - 传感器与车位位置表（`com_parking_bays`）可以通过 `kerbsideid` 进行关联，但车位限制表（`com_parking_restrictions`）仅以 `bayid` 和 `deviceid` 为主键，缺乏官方发布的权威 `kerbsideid <-> bayid` 交叉映射表（Crosswalk）。
   - 在集成人员统一建立权威规则交叉映射前，三表无法闭环，任何传感器物理空闲读数绝不能被标记为“可停”。
4. **节假日与施工盲区门槛（GM-22 / T039 依赖）**：
   - 官方元数据已明确指出公休日传感器不运行，施工区域传感器会虚报空闲。必须由 GM-22 完成维州节假日证据链后方可计算最终车位可用性。
