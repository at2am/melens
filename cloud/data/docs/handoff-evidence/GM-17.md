## 3. 失败关闭与防冒充机制验证 (Fail-Closed & Anti-Forgery)

### 3.1 按范围 ZIP 校验和失败关闭
在 `archive.ts` 中构建了四重校验屏障：
1. **HTTP 范围校验**：`verifyRange` 校验响应长度是否等于 `end - start + 1`，以及 `Content-Range` 头是否严格匹配 `bytes ${start}-${end}/${size}`。若不匹配，抛出 `Content-Range or response length mismatch`。
2. **Local Header 签名校验**：`localDataOffset` 校验本地文件头签名 `0x04034b50` 及压缩方法；若被篡改，抛出 `local header mismatch`。
3. **CRC32 与解压尺寸校验**：`decompress` 函数在解压完成后，严格对比 `crc32(output) !== entry.crc` 与 `output.length !== entry.uncompressedSize`；任何一位字节翻转或截断，立即抛出 `checksum or size mismatch`。
4. **强验证头保证**：若服务端未提供 ETag 且未提供 Last-Modified，抛出 `server did not provide archive validator`。

### 3.2 严禁归档 ETag 假冒 GTFS 版本
1. **语义隔离**：HTTP ETag（如 `"1790344929.3356159-275497665-1743196613"`）是传输层协商标识，不能代表交通机构（Transport Victoria）发布的时间表编次。连接器计算 `sha256(validator + '\n' + outer.size)` 并加上 `archive-sha256:` 前缀，确保其身份标识为归档校验修订，而不是 GTFS feed 版本。
2. **日历安全边界**：由于缺乏 `feed_info`，`validFrom` 和 `validTo` 必须置为 `null`，并在元数据记录中显式标注 `time_missing_reason = "Feed info does not specify calendar start date"`。
3. **跨源关联失败关闭（T066 联动）**：
   在 `gtfs-alerts.ts` 的 `publisherFeedVersion` 逻辑中：
   ```ts
   if (feedInfo.length === 0) return null;
   if (staticFeed.version.normalized.feedVersion.startsWith('archive-sha256:')) return null;
   ```
   - 若静态数据缺少 `feed_info`，或者静态版本以 `archive-sha256:` 开头，或者使用原始 HTTP ETag 字符串尝试匹配，版本匹配判定一律返回 `false`。
   - 警报地理映射状态一律赋予 `version_unverified`，`geometry_geojson` 强制保持 `null`。
   - 绝不因拥有归档 ETag 就伪造坐标或声称版本一致。

### 3.3 2026-10-01 云端集成审查结论同步 (Cloud Integration Review Confirmation)
根据 `specs/001-melbourne-data-aggregation/parallel-followup-2026-10-01.md` 与 `cloud/data/docs/validation/gtfs-integration-review-2026-10-01.md` 的正式审查结论：
1. **官方静态包确实缺失 `feed_info.txt` 的事实保持不变**：官方静态归档（`2/google_transit.zip` 与 `3/google_transit.zip`）确证未包含 `feed_info.txt`，上游缺失发布方版本与日历起止时间。
2. **HTTP archive 校验值（`archive-sha256:`）绝对不能伪装或冒充 publisher 的 `feed_version`**：HTTP ETag / Last-Modified 仅代表传输层缓存凭据，与 GTFS Realtime 标准规范中发布方声明的 `header.feed_version` 性质完全不同。
3. **保持 `version_unverified` 且严禁生成虚构坐标**：经系统云端实测核验，当前在缺乏官方正式可比较版本证据的前提下，任何试图通过复用归档校验串建立关联的做法均被禁止；警报在无官方同版证据时继续严格保持 `version_unverified`，且 `geometry_geojson` 必须为 `null`。
4. **模式独立性原则**：静态火车和电车归档彼此独立；即便未来模式子包出现 `feed_info`，也必须按模式保持对应关系，不能通过拍平混淆或统一哈希替代。
