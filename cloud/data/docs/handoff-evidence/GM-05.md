## 3. 可重复的行为验证

根据数据质量规范与停车推断规则，进行如下行为约束与验证：

1. **旧规则 / 无有效期的历史规则 (Undated / Expired Rules)**:
   - 官方 restrictions 数据缺少生效时间（`valid_from = null`），且上游处理时间为 2022 年。
   - 规则判定函数 `applicable(rule)` 严格执行不变式：“获取的历史未标生效日期的标牌，不是该限制今日仍然有效的证据”（A fetched copy of an undated historical sign is not evidence that the restriction still governs parking today）。
   - 当 `valid_from = null` 或 `valid_to <= now` 时，`applicable()` 均返回 `false`，判定原因记录 `no_current_rule`，决策结果为 `mayParkNow = "unknown"`，绝对不产生肯定许可 (`yes`)。
2. **未知节假日 (Unknown Holidays)**:
   - 当节假日事实未知（`melbournePublicHoliday = null`）时，`ruleConclusion()` 对非 `all_days` 适用的规则直接判定为 `unknown`。
   - `evaluateParkingBay()` 记录 `rule_ambiguous`，决策结果为 `mayParkNow = "unknown"`。
   - 当为法定节假日（`melbournePublicHoliday = true`）且规则为典型非节假日生效（`effectiveonph = 0`，即 `holiday_applicability = "does_not_apply"`）时，规则同样输出 `unknown`，不产生肯定许可。
3. **冲突规则 (Conflicting / Overlapping Rules)**:
   - 连接器导出 `rulesOverlap(a, b)` 与 `findRuleConflicts(rules)`，能够精确识别同一车位在相同日期、重叠时间窗口内出现的冲突规则。
   - 当同一车位被多条重叠规则覆盖且结论不唯一（如同时存在允许与禁止规则，或多条重叠允许规则），`conclusions.length !== 1` 判定为 `rule_ambiguous`，决策结果为 `mayParkNow = "unknown"`。
4. **车位跨表键缺失 (Missing Rule Crosswalk)**:
   - 限制规则中 `bayid` 无法与实时传感器的 `kerbsideid` 建立可核实连接，连接器将 bay ID 严格命名空间化为 `restriction_bay:${bayid}`。
   - 若无经独立核实的有效 crosswalk（`ruleCrosswalk = null`），判定原因记录 `rule_crosswalk_unverified`，`mayParkNow` 保持 `unknown`。
5. **元数据最后处理时间保留**:
   - `ParkingRestrictionsConnector` 现支持通过 `fetchMetadataRevision()` 或 `fetchMetadataRevision: true` 选项自动从 Catalog Metadata 提取 `2022-11-13T10:30:19.000Z`。
   - 在上游 Records API 未下发 `Last-Modified` HTTP 响应头时，保持版本与时效追溯完整性。

## 5. 仍阻断的门槛与后续交接事项

1. **静态数据与有效日期阻断**:
   - 上游数据为 2022-11-13 的静态历史规则，缺乏当前生效的规则日期及实时变动通知。
   - 在上游发布带有明确有效期的现行规则前，所有从该来源提取的规则在实时停车评估中必须保持 `mayParkNow = unknown`。
2. **三表关联阻断 (T035)**:
   - 规则数据集的 `bayid`/`deviceid` 与传感器数据集的 `kerbsideid` 之间不存在官方交叉映射表。在由官方或集成团队提供可审计的映射证据前，车位与规则无法打通。
3. **准入与许可复核**:
   - 本连接器数据清单 `source.json` 保持：
     - `license_status: "review_required"`
     - `access_status: "candidate"`
