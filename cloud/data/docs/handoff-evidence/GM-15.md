## 3. 本地契约、时区规则假设与风险分析

### 3.1 端点专属时区规则、假设与风险深度说明

> [!WARNING]
> **关键治理与架构原则**：
> 1. **严禁跨端点推断**：计划道路端点（`tv_road_planned`）与非计划道路端点（`tv_road_unplanned`）是独立发布的数据集，**绝不能假定两者共享时区逻辑**。非计划道路端点在云端实测中因直接按 UTC 解析导致 16 条事实超前抓取时刻落在“未来”，而计划道路端点经维州本地转换后落在抓取前 10 小时。
> 2. **“无未来时间”并非转换正确的充分证明**：将 `2026-09-30T23:55:20` 解释为维州夏令/冬令时间（得到 `13:55:20Z`）虽然在数学上小于抓取时刻（`23:58:19Z`），消除了“未来时间异常”，但这**仅仅表明在因果时间上合理，绝不代表上游发布者的真实意图一定是 AEST/AEDT**。上游完全可能在生成该字符串时使用了未校准的内部服务器时区，或原本就意图输出 UTC 却遗漏了 `Z`。
> 3. **夏令时歧义与不可跳过性（Fail-Closed）**：若上游确实使用维州本地时间，则在每年 4 月第一个周日的时钟回拨重叠小时（02:00-03:00 重复出现），相同时间戳会产生歧义。`parseVictorianTimestamp` 必须对该区间的无 offset 时间严格抛出异常阻断，绝不允许静默猜选。
> 4. **阻断结论**：在未取得 Transport Victoria 官方书面规范或明确技术响应前，该时区转换保持为**候选推测假设（Candidate Working Hypothesis）**，构成本数据源从 candidate 晋升为 ready/active 的核心门槛之一。

### 3.2 计划事件生命周期与取消状态契约

- **取消事件规范化**：
  - 上游返回 `status: 'Cancelled'` 或 `'Canceled'` 时，`classifyPlannedStatus` 将其映射至：
    - `SourceRecord.record_status = 'cancelled'`；
    - `GeoRecord.record_status = 'cancelled'`；
  - 核心属性（封闭路段名称、起止交叉口、影响车道、几何形状、原定时间）全量保留，作为历史取消存证；
- **下游视图生命周期隔离**：
  - 当前道路变化视图（`v_transport_changes_current`）通过 `record_status NOT IN ('cancelled', 'resolved', 'withdrawn')` 排除已取消事件；
  - 全量历史视图（`v_change_timeline`）计算 `time_state = 'cancelled'`，实现“展示历史取消记录，但绝不宣称当前道路受阻”。
- **未来与生效状态演进**：
  - `start > fetchedAt` 或 `status === 'Pending'` 时，空间记录状态严格保持 `'planned'`；
  - 仅当事件处于工程期内（`start <= fetchedAt` 且未结束）且源状态为 `Active` 时，状态才晋升为 `'active'`；
  - 完工或结束事件（`Completed` / `Resolved` / `Inactive` / `Closed`）映射为 `'resolved'`。

### 3.3 重放幂等性与版本控制（Replay Idempotency）

- **版本计算规则**：`sourceVersionId(updatedAt, content)` 基于 SHA-256 递归规范化键排序计算；
- **重放不变式**：无论运行多少次、分配何种 `batch_id` 或在何时抓取，只要上游输入的 Disruption ID、属性与几何不变：
  - `source_record_id` 绝对恒定；
  - `version_id` 绝对恒定；
  - `geo_record_id` 绝对恒定；
  - `valid_from` 与 `valid_to` 绝对恒定。
- **内容演进敏感性**：一旦上游 `lastUpdated` 推进或 `description` / `impact` 发生变化，立即生成全新的 `version_id`，同时保持物理 ID 关联。
