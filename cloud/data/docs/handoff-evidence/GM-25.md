## 3. 真实调用断言与边界阻断验证说明

### 3.1 真实调用链路 (Real Production Pipelines)
测试完全脱离自写假数据模拟，调用生产模块真实执行：
- `normalizeRentalPayload` + `normalizeHomesVictoriaRents` (Homes Victoria Rents)
- `normalizeCsaStatistics` (CSA Recorded Offences)
- `normalizeCensusPayload` + `normalizeAbsCensusStatistics` (ABS Census)
- `normalizeClueEmploymentRow` + `normalizeClueEmploymentStatistics` (City of Melbourne CLUE)
- SQLite `DatabaseSync` 运行 `sql/006_area_views.sql` 中完全相同的视图逻辑 (`v_boundaries` 与 `v_area_indicators`)。

### 3.2 两个地区验证 (Two Regions)
- **Region 1**: Melbourne LGA (`ASGS_LGA:24600:2025`)
- **Region 2**: Yarra LGA (`ASGS_LGA:27350:2025`)
- 在真实 SQL 视图查询中分别验证：
  - Melbourne 租金：2024-Q4 (615 AUD/wk) 与 2025-Q1 (680 AUD/wk)，`boundary_mapping_status = 'matched'`，`boundary_name = 'Melbourne'`。
  - Yarra 租金：2024-Q4 (675 AUD/wk) 与 2025-Q1 (700 AUD/wk)，`boundary_mapping_status = 'matched'`，`boundary_name = 'Yarra'`。
  - CSA 犯罪统计：Melbourne 2025 (26000) / 2026 (28450)；Yarra 2025 (10500) / 2026 (11200)，全部匹配正确地区名称与代码。

### 3.3 两个统计期验证 (Two Statistical Periods)
- **Period 1**: 2024-Q4 (`2024-10-01T00:00:00Z` ~ `2025-01-01T00:00:00Z`)
- **Period 2**: 2025-Q1 (`2025-01-01T00:00:00Z` ~ `2025-04-01T00:00:00Z`)
- 通过真实 Batch 发布、SourceRecord 关联入库，视图按 `period_start` 排序返回，精确可追溯至 `batch_id` 与 `source_record_id`。

### 3.4 抑制与缺失值阻断保护 (Suppression / Null Preservation)
- 当租金或犯罪数据源标记为低频抑制（如 `<4`、`-`、`*`）或数据缺失时：
  - 生产 Normalizer 严格赋予 `status: 'suppressed'` 或 `'missing'`，`value: null`。
  - `enforceAreaIndicatorInvariants` 断言：非 `observed` 状态的数值必须为 `null`，禁止填零。
  - SQL 视图 `CASE WHEN i.status = 'observed' THEN i.value ELSE NULL END AS value` 确保输出 `value IS NULL`。
  - 测试断言：`assert.equal(row.value, null)` 且 `assert.notEqual(row.value, 0)`。

### 3.5 未匹配租金不能静默 join (Unmatched Rents Fail-Closed)
- 当输入数据包含不在官方边界目录中的区域（如 Buloke、French Island、Unknown Region）：
  - 生产 Normalizer 拒绝模糊匹配，生成 `:unresolved` 结尾的 boundary ID（如 `VIC_LGA_NAME:buloke:unresolved`）。
  - SQL 视图中 `LEFT JOIN v_boundaries` 无法匹配，派生字段 `boundary_mapping_status = 'missing'`。
  - 关联的边界字段（`boundary_scheme`、`boundary_code`、`boundary_name`、`boundary_vintage`）严格为 `NULL`，**绝不静默吸附到 Melbourne 或 Yarra**。
  - 跨年份边界隔离：拥有 `2026` vintage 标记的指标绝不静默 join 到 `2025` 或 `2021` 的同名 LGA。
  - 领域级断言：未匹配指标传入 `assertComparableIndicators` 时强制抛出异常阻断。

## 5. 接口与共享契约建议（供架构师与公共模块维护者参考）

1. **`assertComparableIndicators` 函数的语义细分**：
   - 当前 `assertComparableIndicators` 的判断条件要求两者的 `boundary_id` 严格相等（或在 `explicitMapping` 中存在映射）。这在验证“单一区域跨时间段序列比较”时非常有效。
   - 但是在“同一年份同一统计期横向对比两个不同地区（如 Melbourne LGA vs Yarra LGA）”时，由于两者的 `boundary_id` 不同，直接调用会触发抛错。
   - **建议**：未来可以在契约中区分两种比较语义：
     - `assertComparableTimeSeries(from, to, crosswalk?)`：用于同一区域跨时段或跨版次比较（强制要求同 boundary 或跨年映射）。
     - `assertComparableCrossSection(indA, indB)`：用于横向对比，仅检查两者的 `unit`、`assertion_kind`、`period` 是否一致，且双方的 `boundary_id` 均已成功解析（非 unresolved/missing）。
2. **Homes Victoria 租金跨表映射规范化**：
   - 目前 Homes Victoria 原始数据中的 Suburb 名和 LGA 名存在部分拼写与大小写差异，建议结合 GM-21 的调研成果，在 `AreaBoundaryEvidence` 中建立官方代码（如 ABS LGA Code）映射索引，避免仅依赖字符串名称转换。
