### 2.4 云端实盘探查与无时区偏移时间戳证据 (Cloud Probe & Offsetless Timestamps)
- **探查响应时刻**：`2026-09-30T23:53:48.526Z`
- **要素总数与特征**：共拉取到 291 个 Feature，其中 290 个要素的 `lastUpdated`（以及部分 `created`、`lastClosed`）字段为无时区偏移的本地 ISO 时间字符串（例如 `2026-10-01T09:49:04`）。
- **UTC 误解析后果与未来时间扭曲**：
  若在运行于 UTC 的 Cloud Run 或服务器上直接调用 `Date.parse("2026-10-01T09:49:04")`，系统会将其默认为 `2026-10-01 09:49:04 UTC`。这导致时间戳比探查拉取时刻快了 9 小时 55 分钟，使得 16 条事实记录的时间戳落入“未来时间”，严重破坏因果一致性与单调性。
- **维州本地时区假设 (`Australia/Melbourne`) 与校正效果**：
  连接器建立并实施维州官方时区规则假设（`Australia/Melbourne`，AEST UTC+10 / AEDT UTC+11）。
  2026-10-01 当天处于澳大利亚东部标准时间（AEST, UTC+10）。
  将 `2026-10-01T09:49:04` 转换为 UTC：`2026-09-30T23:49:04.000Z`。
  此时间严格早于探查响应时刻（`2026-09-30 23:53:48.526Z`）约 4 分 44 秒，未来时间记录数归零，完全符合物理时序与数据生成逻辑。
- **严格夏令时 Gap 与 Fold 防御**：
  维州本地时间每年经历两次夏令时跳变：
  1. **漏时跳变 (DST Gap)**：10 月第一个星期日凌晨 02:00 -> 03:00（如 02:30 不存在）；
  2. **折叠重复 (DST Fold)**：4 月第一个星期日凌晨 03:00 -> 02:00（如 02:30 出现两次，具有歧义）。
  连接器在 `parseVictorianTimestamp` 中通过计算 UTC+10 与 UTC+11 候选时刻在 `Australia/Melbourne` 下的往返格式化比对，当且仅当候选匹配数唯一（`matches.length === 1`）时才接受解析；若落入 Gap 或 Fold，立即拒绝并返回 `null`，避免将不确定的时间数据存入图谱。
- **禁止使用无偏移时间戳认证新鲜度**：
  在缺乏上游官方明确时区与时钟同步元数据的前提下，禁止使用无偏移时间戳认证数据版本的绝对新鲜度（Freshness Certification）或进行跨数据源的次分钟级严格偏序判断。

## 3. 可重复的行为验证与核心契约

已通过离线契约与仿真测试，严格验证如下行为契约：

1. **父事故与子影响关联 (Parent-Child Invariant)**：
   - 同一父事故（`id: RUD-INC001`）下的多个影响（`IMP-1`, `IMP-2`），其父事故 `SourceRecord` 按版本去重（仅相同版本去重，演进版本完整保留）；
   - 每个受影响路段生成独立的 `impact` 级 `SourceRecord` 与 `GeoRecord`；
   - 每个子影响的 `GeoRecordSources` 严格保留双重追溯：`evidence_role = "parent_incident"` 指向父事故，`evidence_role = "child_impact"` 指向子影响；
   - 对于无子影响的单一事故（`impactId = null`），降级为由父事故作为 `geo_record_id`，仅保留 `parent_incident` 追溯；
   - 集合内出现同批次重复 `(id, impactId)` 时立即抛出异常并触发 `validation_failed`。
2. **解除状态、时间真实性与幂等重放 (R02 Clearance & Idempotency)**：
   - 处于 `Active` 状态的事故：`record_status = 'active'`, `valid_to = null`；
   - 处于 `Inactive` 状态且具备官方解除时间的事故：`record_status = 'resolved'`, `valid_to = lastClosed`；
   - **R02 核心修正**：若上游标记 `Inactive` 但未提供 `lastClosed`，严格保持 `valid_to = null`，绝不拿 `fetchedAt` 冒充结束时刻；在 `SourceRecord.time_missing_reason` 明确标为 `"Incident clearance time absent upstream"`；
   - **重放一致性**：相同的 Inactive payload 在不同 `fetchedAt` 归一化时，`version_id`、`valid_to`（均为 null）、`observed_at`、`valid_from` 100% 一致，杜绝不同抓取时间生成不同版本或不同结束时间的非幂等问题；
   - `endTime` 属性仅作为预测/估算终点，严格禁止根据 `endTime` 判定解除（符合官方文档规范）；
   - 所有生成的 `SourceRecord` 均通过 `parseSourceRecord()` 严格校验；所有 `GeoRecord` 均通过 `validateGeoRecordGeography()` 校验。
3. **60秒源时间与分页限额 (60s Cadence & Rate Limiting)**：
   - `sourceLatestUpdateAt` 与 `sourceRevision` 取快照中所有要素的最大 `lastUpdated`；
   - 上游缺失 `created` 时，设置 `observed_at = null` 并在 `time_missing_reason` 记录证据说明；
   - 设定默认 3.1 秒跨页请求延迟，确保即使在深分页遍历下，调用频率（~19次/分）严格处于官方 20次/60秒 限流红线之内。
4. **限流与异常失败路径 (Failure Handling)**：
   - HTTP 429 时捕获 `rate_limited` 错误码，优先按 `Retry-After` 解析等待秒数，缺省时按 60 秒设置 `retryAfterSeconds`；
   - 多页拉取时，若第 2 页触发 429，立即终止并返回失败，不提交残留的不完整要素；
   - KeyID 缺失直接返回 `auth_failed`，不产生网络开销；
   - 无论成功或失败，绝不在 `result.message`、URL 参数或错误追踪中输出 KeyID。
5. **时区解析、夏令时防御与预估隔离契约 (Timezone, DST & Forecast Isolation)**：
   - 带有时区偏移（如 `Z`、`+10:00`）的时间戳按 ISO-8601 标准直接换算为 UTC；
   - 无偏移时间戳按 `Australia/Melbourne` 本地时间换算，通过候选偏移校验严格防御夏令时 Gap 与 Fold（若匹配数不为 1 则置 null 并记录原因）；
   - 严禁以无偏移时间戳认证版本绝对新鲜度或确定次分钟排序；
   - 严格隔离实际解除状态与预估时间：`endTime` 与 `nextUpdateDue` 仅作为普通属性保存在 GeoRecord 中，过期不触发 resolved，解除必须以 `status === 'Inactive'` 或 `eventLocationStatus === 'Inactive'` 结合 `lastClosed` 为准。
