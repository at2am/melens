# City of Melbourne CLUE blocks: admission evidence

Reviewed 2026-09-30 Melbourne time. The [official CLUE blocks dataset](https://data.melbourne.vic.gov.au/explore/dataset/blocks-for-census-of-land-use-and-employment-clue/) describes the layer as CLUE block polygons and says the boundaries were realigned during 2025. The [official API metadata](https://data.melbourne.vic.gov.au/api/explore/v2.1/catalog/datasets/blocks-for-census-of-land-use-and-employment-clue) identifies the dataset and declares `CC BY` with a [CC BY 4.0 licence URL](https://creativecommons.org/licenses/by/4.0/legalcode). The licence permits copying and redistribution with attribution. Product use must credit City of Melbourne, link to the dataset and licence, and identify that Melens converted the geometry for its map.

The public records API reported 603 records on 2026-09-30. A live, read-only connector probe fetched all 603 records in seven pages, validated 603 distinct block IDs and polygon geometries, and rejected none. Its fetch completed at `2026-09-30T04:21:48.866Z`. The manifest's `coverage_from = 2026-09-30T04:21:48Z` means the first fully verified current snapshot. It is **not** an effective date for every 2025 block boundary. The connector labels the official current alignment `vintage = 2025` and refuses requests for historical vintages.

The API response advertised `X-RateLimit-Limit: 10000` with a next-day UTC reset. That is an observed unauthenticated portal limit, not a request target or a guaranteed service level. One full snapshot currently uses seven requests. The connector collects only `block_id`, `region_name`, `area_name`, and `geo_shape`; it keeps no raw response body. Temporary BigQuery load files should be removed after publication, with orphan cleanup within one day. A cloud one-shot should use an operational request cap far below the observed portal limit.

The source is now `verified_open` / `active` after a one-shot development publication. Batch `batch_f0a0eb72161ea86f7a9923c6b1ba32d02706b3f8` reached `published` with 603 inputs, 603 outputs and no rejections. BigQuery holds 603 source records with verified rights and 603 boundary rows; `melens_query.v_boundaries` exposes 603 distinct 2025 block polygons, all with non-null geography. A second run returned the same batch ID, and the ingest bucket had no remaining objects. The [CLUE vintage policy](clue-vintage.md) still forbids a block-ID join between the 2025 polygons and 2002–2024 employment statistics. The deployed view now selects later corrections by the exact same-batch source record's timestamp or ordinal; unordered multiple versions fail closed. Recurring source publication remains disabled pending the shared scheduling and budget gates.
