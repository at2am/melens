# City of Melbourne municipal boundary: admission evidence

Reviewed 2026-09-30 Melbourne time. The [official dataset metadata](https://data.melbourne.vic.gov.au/api/explore/v2.1/catalog/datasets/municipal-boundary) identifies `municipal-boundary` and declares a **CC BY 4.0** license URL. Its [records endpoint](https://data.melbourne.vic.gov.au/api/explore/v2.1/catalog/datasets/municipal-boundary/records?limit=1) returned one `City of Melbourne` feature, with `mccid_gis = 1` and `xdate = 2008-07-01`. The connector's live public probe also returned one validated boundary and one source record. The 2026-09-30 response advertised `X-RateLimit-Limit: 10000` and a next-day `X-RateLimit-Reset`; this is the observed unauthenticated portal ceiling, not a request target. `coverage_from` records this source's boundary vintage, not a claim that every historical council boundary is present.

The connector uses `mccid_gis`, `name`, `xdate`, and `geo_shape` only. It retains no raw response body. Temporary BigQuery load files are deleted after successful publication and carry a one-day expiry timestamp; cleanup of orphaned files still needs cloud deployment. Product use must attribute City of Melbourne and link to the official dataset.

On 2026-09-30, the source was admitted as `verified_open` / `active` and published once to the development BigQuery datasets in project `melens-510012`. Batch `batch_36504f107a03dd7e69919f81b27113f0e29dceea` reached `published` with one input, one boundary output and no rejections. `melens_query.v_boundaries` returned one `com_municipal:1:2008-07-01` feature with non-null geography (area about 37.6 km²); the source record had `rights_status = verified_open`. A second run of the same snapshot returned the same batch ID, leaving one stored boundary row and one visible boundary. The ingest bucket had no remaining objects. This proves a one-shot development publication, not recurring Cloud Run/Scheduler operation or the eight-category first-release gate.
