# Events source admission and coverage

## Ticketmaster Discovery API

- The [Discovery API v2 documentation](https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/) describes key authentication, 5,000 requests per day by default, 5 requests per second, zero-based paging, and a 1,000-result deep-paging boundary. The connector uses a bounded event-start window and fails an oversized search instead of silently truncating it.
- The upstream search is an approximate 80 km circle around central Melbourne, restricted to Australia/Victoria. It is neither the City of Melbourne municipality nor an official Greater Melbourne boundary. The source only covers events on participating Ticketmaster platforms; it cannot certify that no local activity exists.
- The [general API terms](https://developer.ticketmaster.com/support/terms-of-use/), rechecked 2026-10-01, allow reasonable caching for the service and require application removal within 24 hours after an owner request. They restrict replacement of the Ticketmaster experience and commercial API exploitation. The 24-hour requirement concerns requests to remove content; it is not a universal cache duration in these terms. This release uses minimal metadata as Melbourne map context and links to the original event. It does not retain promotional descriptions, media, ticket inventory, orders or attendee information. A later monetized use requires a fresh terms review.
- The application adopts a 24-hour content visibility cap and a 12-hour complete refresh. All event fields in current/history query views expire by fetch age. Every 6 hours, cleanup removes source content older than 18 hours, keeping normal storage within the 24-hour target. A rights request withdraws the whole source and removes all its retained content. Stored paused permission prevents subsequent publication. Raw responses are not retained. Attribution is `Event information provided by Ticketmaster`, and each record keeps its direct source link. The coordinator activated the `restricted` manifest after the real private cloud snapshot collected 421 events at `2026-10-01T11:48:53.540Z`, including 372 eligible future events at 38 provider venues. The release validation document records deployed query, cleanup and publication evidence separately.
- A developer API key already exists as an enabled Secret Manager version. Cloud Run injects it through `TICKETMASTER_DISCOVERY_API_KEY`; local reads and credential-bearing request logs are prohibited. Key-bearing requests reject redirects and make one network attempt, so each request is accounted for. A 350 ms page gap stays below the documented 5 requests/second. The application daily cap is 40 requests, below the upstream default 5,000/day.

The coordinator's first formal publication is batch `batch_77e407d3dc317380ca8c849c862cca2c4e929dfe`: 421 input/output records with zero rejects. BigQuery readback returned 419 non-cancelled current events, including 372 future events with known dates, and 419 source venue points/direct links. The 12-hour schedule is enabled, authenticated Scheduler dispatch produced a second successful real event execution, and the natural 12:11 retention job succeeded. The next natural event invocation, expired-content deletion totals and controlled removal remain follow-ups. The [release validation](../validation/events-release-2026-10-01.md) distinguishes these observations.

### Query and deletion policy

| Data | Application storage policy |
| --- | --- |
| Native event ID, title, direct URL, schedule/status, venue identity/coordinate | Retain as a source cache, query only while `0 <= now - fetched_at < 24 hours` and the event is not suppressed. |
| Source/geo/evidence rows from previous snapshots | Same 24-hour visibility bound. Use the latest complete published snapshot for current membership so a disappeared event is not revived. |
| Raw API response, descriptions, images, ticket/order/attendee data | Do not retain. |
| GCS staging containing event metadata | Delete content older than 18 hours every 6 hours; no expired content visible through query views. Successful publication removes staging immediately. |
| Sync audit and quota totals | Keep only operational counts, timestamps, source/batch IDs and hashes. Remove staged object references when their objects are removed. |
| Owner-requested removal | Withdraw the entire Ticketmaster source, immediately blocking its query access, then delete all its source/geo/evidence versions and GCS copies under the source publication lease. Persisted paused permission prevents re-publication. Individual event filtering can be added later. |

BigQuery may retain deleted data in its managed recovery copies for the configured time-travel/fail-safe period. Application views must not expose these copies, and query consumers must not have access to the underlying warehouse. Cleanup does not claim immediate erasure from cloud-managed recovery storage.

Snapshot ingestion computes a future 30-day event-start window at run start. Explicit time windows remain available for bounded probes. The connector requires all page sizes, counts and totals to agree, rejects duplicate event IDs and any search exceeding the 1,000-result boundary, and never publishes a partial result. A missing end remains null. Several venues do not become an arbitrary single venue point. Rescheduling and cancellation change the content version while preserving the event ID. Status is retained as the provider reports it.

## Other everyday activities

The [City of Melbourne open-data catalog](https://data.melbourne.vic.gov.au/explore/) has historic event permits and bookable venues, which are different from a current public event calendar. [DataVic's City Activities and Planned Works catalog entry](https://discover.data.vic.gov.au/dataset/city-activities-and-planned-works) describes permitted works and event bookings under CC BY. Its linked v2.1 records API still returned HTTP 404 during the 2026-10-01 read-only recheck. Its update frequency is unknown. Catalog title searches returned three event datasets, historic permits, historic Melbourne Conversations and venue bookings; none is a current calendar. The activity search additionally found sound-stage sensor datasets without a declared license and development datasets, which do not provide a current activity calendar.

The [What's On Melbourne](https://whatson.melbourne.vic.gov.au/) calendar includes free/community events. Its [copyright notice](https://whatson.melbourne.vic.gov.au/disclaimer) does not grant general commercial reuse, and a supported ingestion API has not been established. It is not selected for automated ingestion. Ticketmaster includes participating Universe and FrontGate platforms, but that does not establish coverage of all daily/free/community activity. This release must state its platform coverage. A permitted broader current-calendar source remains a follow-up, rather than presenting an unlicensed scrape or historic permits as present-day events.
